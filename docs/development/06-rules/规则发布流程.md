# 规则发布流程

> 版本：v1.1 候选｜状态：按新 MVP 知识治理修订中
> 负责人：内部规则负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：规则 Schema v1.0、金标建设规范 v1.0

## 1. 生命周期

`draft → review → evaluated → approved → published → deprecated → retired`

紧急状态：`suspended`，用于立即停止新运行使用；历史结果保留。

## 2. 角色分离

- Author：编写规则和样例；
- Reviewer：核验业务逻辑与依据；
- Evaluator：运行并解释评测；
- Approver：批准生产发布；
- Operator：执行发布和回滚。

Author 与 Approver 首期应分离。

## 3. 发布门禁

- 规范依据有效且版本明确；
- 企业立场适用范围明确；
- Rule/Slot Schema 校验通过；
- 正例、反例、缺材料、冲突和边界样例通过；
- 高风险漏报和无证据结论符合门槛；
- 影响分析列出需重审的案件或规则；
- Skill、执行器和报告兼容性确认。

## 4. 法规变化

新规范先入候选库并做 diff，生成受影响规则列表。法务批准后发布新规则版本；历史运行不自动改写，需要复核时创建新运行。

法律原文版本先记录权威来源、原文哈希、公布/施行/失效时间、条款位置及法律复核人，批准后才可被正式规则引用。企业知识先记录所属企业、材料授权、批准人、有效期间与发布状态；LLM-Wiki 只能整理候选，企业知识负责人确认发布后才可被正式引用。知识发布不自动改变运行用 Skill：规则/Skill 须重新绑定并发布新版本，旧运行保持原绑定。开发用 MD Skill 不进入本流程的 `published` 状态。

## 5. 回滚

回滚只影响新运行的规则选择。若已发布规则可能造成严重误导，应 suspended，识别受影响运行，通知负责人并建立复核任务。

## 6. 环境晋级

| 环境 | 允许状态 | 要求 |
|---|---|---|
| dev | draft, review, evaluated | 可使用开发集，不得生成正式报告 |
| test | evaluated, approved | 固定产物哈希，运行回归与安全测试 |
| mvp | published | Approver 记录、评测报告和回滚目标齐全 |

`approved_for_development` 只表示允许研发实现和运行种子集，对应生命周期中的 draft/review 阶段，不等于 `approved` 或 `published`。

## 7. 开发态产物审查

运行 `scripts/audit_rule_release.py` 可生成一份确定性的开发态审计清单，将 RuleDefinition、生成的 Markdown Skill、评测套件/fixture 与可选评测报告的版本及 SHA-256 交叉绑定。审计器会验证报告内部哈希，以及报告所引用的规则、套件和 fixture 是否与当前输入完全一致；同时核对逐例 ID 集合，v1.1/v1.2 报告还须逐项匹配 suite 声明的样例类别，不能仅靠重算自哈希替换样例。v1.2 还绑定缺失类别清单。法律原文引用与企业立场引用分别列出，不存在内容哈希时明确标为 `unresolved`。

```bash
uv run python scripts/audit_rule_release.py \
  --rule docs/development/06-rules/rules/legal.payment_conditions.v1.yaml \
  --suite docs/development/06-rules/eval/legal.payment_conditions.cases.yaml \
  --knowledge-manifest /secure/knowledge/manifest.json \
  --evaluation-report /secure/evaluation/payment-report.json \
  --output /secure/evaluation/payment-release-audit.json
```

`--knowledge-manifest` 可选，格式为 `{"manifest_version":"development-knowledge-manifest.v1","sources":[{"reference":"<规则中声明的稳定引用>","kind":"normative 或 enterprise_position","path":"相对清单的本地文件路径"}]}`。它只核对每个引用的类别并计算原始文件字节 SHA-256；相对路径必须留在清单目录内，拒绝路径逃逸和符号链接。审计产物只包含引用、类别、哈希和 `content_bound_unapproved` 状态，不复制正文，不证明发布方、权威性、有效时间或批准身份，也不会把这些材料注入 Skill/模型上下文。缺失内容继续标为 `unresolved`；即使所有正文均已绑定，仍保留 `knowledge_source_approval_missing` 发布阻断。

该命令只构造审查材料，不具备批准/发布接口，`release_ready` 永远为 `false`、退出码为 2；即使报告内部完整且 case 全通过，也不能替代批准阈值、依据正文、审批人、签署身份或回滚目标。输出文件以 `0600` 新建并拒绝覆盖。该 SHA-256 清单用于发现产物错配和意外变化，不是数字签名或可信构建证明，不得据此将开发候选提升到 test/mvp。
