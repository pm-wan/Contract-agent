# 合同价款开发评测 observations（中文可读版）

## 一、observations 是什么

本套件的 `observations` 是人工编制的合成开发回归值，不是系统实际运行输出。它们用于验证评测器的字段匹配、覆盖统计和完整性流程；不能证明 Worker、模型或提示注入防护的行为。

它不是合同原文，也不是法律结论；它用于和评测套件中的“预期结果”逐项比对。下文“开发预期”是人工标注，不应称为实际“系统判断”。当前 Worker 的价款 `TaskResult.judgment` 保持 `undetermined`，持久任务 API 使用统一的 `price_review` 类型；`human_review`、`needs_material` 和 `finance_review` / `legal_review` 是评测分类标签，不是现行 API 输出值或独立的真实任务路由。

## 二、逐条翻译

### 1. 正常税额案例

- 案例编号：`price-consistent-001`
- 合同内容：含税价1130元、未税价1000元、税额130元，未明确写币种。
- 开发预期：暂不形成最终结论。
- 已识别内容：
  - 价款基础：已找到
  - 价款来源：已找到
  - 付款分母：已找到
- 开发标签：无专门复核分类（并不证明运行时不会创建通用 `price_review` 任务）。
- 开发默认：未写币种时按人民币处理。

### 2. 税额冲突案例

- 案例编号：`price-tax-conflict-001`
- 合同内容：含税价1130元、未税价1000元，但税额写成200元。
- 开发预期：人工复核。
- 评测标签：财务复核（不是当前 API 的独立任务类型）。
- 原因：1130 − 1000 = 130，与原文税额200不一致。

### 3. 固定金额与比例冲突案例

- 案例编号：`price-fixed-percentage-conflict-001`
- 合同内容：固定付款金额100元，同时约定按合同总价1200元的10%付款。
- 开发预期：人工复核。
- 评测标签：财务复核（不是当前 API 的独立任务类型）。
- 原因：10%应为120元，与固定金额100元不一致。
- 开发处理：固定金额优先，但保留不一致提示。

### 4. 付款分母缺失案例

- 案例编号：`price-missing-denominator-001`
- 合同内容：只写“支付合同总价的30%”，但没有合同总价。
- 开发预期：材料缺失。
- 评测标签：补充材料（不是当前 API 的独立任务类型）。
- 原因：没有分母，不能计算具体付款金额。

### 5. 正文与价款表冲突案例

- 案例编号：`price-source-conflict-001`
- 合同内容：正文总价100万元，价款表合计120万元，未约定哪一个优先。
- 开发预期：人工复核。
- 评测标签：法务复核（不是当前 API 的独立任务类型）。
- 原因：两个优先来源的金额冲突，系统不能静默覆盖其中一个。

### 6. 多币种边界案例

- 案例编号：`price-multicurrency-001`
- 场景：CNY 与 USD 金额合并付款，但没有汇率来源和折算日期。
- 开发预期样例：人工财务复核，不自动换汇或形成确定金额。

### 7. 重复付款阶段边界案例

- 案例编号：`price-repeated-stage-001`
- 场景：两次出现相同的交付后付款阶段，未说明是否为不同期次。
- 开发预期样例：人工财务复核，不静默去重。

### 8. 无价款反例

- 案例编号：`price-no-amount-001`
- 场景：价款留待后续协议，当前材料没有金额或付款安排。
- 开发预期样例：标记材料缺失，不猜测金额。

### 9. 指令注入安全样例

- 案例编号：`price-injection-001`
- 场景：价款条款中夹有要求绕过复核的文本。
- 开发预期样例：保留人工法务复核。此样例的观察值是人工编制，不是实际模型抵御注入的验证结果。

### 10. 价款候选缺少证据

- 案例编号：`price-evidence-missing-001`
- 场景：原文含有价款，但 observation 明确记录空证据数组。
- 开发预期样例：人工法务复核；评分器要求显式空数组，未提供 `evidence` 字段会记为未观测。

## 三、字段对照

| 机器字段 | 中文含义 |
|---|---|
| `case_id` | 案例编号 |
| `judgment` | 合成开发预期标签；不是当前 TaskResult 的实际判断字段 |
| `human_task` | 人工编制的预期处理分类；不是当前 API 的实际任务类型 |
| `slot_status` | 各个规则信息项是否已找到 |
| `undetermined` | 暂不能确定，不代表通过 |
| `human_review` | 必须人工复核 |
| `needs_material` | 缺少材料，需补充 |
| `filled` | 已从原文找到候选信息，不代表最终正确 |

## 四、重要说明

这些结果是开发阶段的结构化回归输入，主要确认评测工具链对边界标签和预期状态的一致性。要验证真实系统处理，必须另行执行冻结的 Worker/模型并审阅输出、证据引用及来源版本；本报告不能替代这项执行。
