# 付款口径决策表（开发草案）

> 状态：**开发阶段已确认（dev-confirmed）**。以下默认值直接用于产品开发和开发态运行；正式生产制度、法律复核和企业审批后续可替换，不阻塞当前产品完成。

## 一、已确认的总原则

| 项目 | 开发阶段默认口径 | 需确认事项 |
|---|---|---|
| 规则名称 | 合同价款口径检查 | 确认正式中文名称及版本号 |
| 总价 | 含税总价、未税总价分别保存；不能用一个字段替代 | 各类合同是否均要求两者，税额如何反推 |
| 币种 | 暂不支持多币种；未提及币种也按人民币处理 | 是否允许个别合同覆盖默认币种 |
| 金额来源 | 正文和价款表优先；附件、补充协议可纳入，但必须逐项核算并提示冲突 | 正文与价款表冲突时的最终优先级 |
| 比例分母 | 默认以合同总价为分母 | 阶段价款、未税总价等例外场景 |
| 固定金额与比例 | 通常二选一；两者同时出现时核算一致性。不一致时固定金额优先，但必须提示 | 允许差额、四舍五入和容差 |
| 缺失/冲突/无法计算 | 不阻断整份合同审核；受影响判断标记“无法判断/需人工核对”，并说明原因 | 是否增加风险等级 |
| 证据 | 每个判断必须展示原文、原文位置；多个位置全部展示 | 位置格式和最小引用长度 |

## 三、统一状态

- **可计算**：金额、分母、币种和来源均有证据，计算结果一致。
- **需人工核对**：关键因素缺失、来源冲突、币种非人民币、计算结果不一致或材料不完整。
- **不阻断原则**：某个价款判断需人工核对时，继续审核违约责任、交付周期等其他具备证据的事项。
- **证据要求**：输出原文文本、文件名/附件名、页码或段落位置、来源版本；同一判断涉及多个位置时全部展示。
