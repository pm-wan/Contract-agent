# 付款规则反例案例草案（待业务核对）

> 状态：**开发阶段已确认**。以下案例由正常付款案例改写，直接用于产品开发回归；它们不是正式合同或生产金标。

| 编号 | 改写场景（示例原文） | 预期提示 | 必须展示的证据 | 用户核对 |
|---|---|---|---|---|
| C-01 | “合同签订后3日内支付合同价款100%。”全文没有交付/验收条件 | 高预付、缺少履约触发条件；人工核对 | 正文付款条款、缺失的验收条件检索范围 |  |
| C-02 | 正文写“合同总价100万元”，价款表合计120万元，未写优先级 | 金额冲突，不阻断其他审核 | 正文总价和价款表合计全部位置 |  |
| C-03 | 正文写“预付30%”，附件付款表写“预付40%” | 比例冲突；合同总价分母可确认但阶段比例需人工 | 正文、附件名称/版本/页码 |  |
| C-04 | 含税总价113万元、未税总价100万元、税额13万元 | 计算一致，可记录人民币默认 | 三个金额原文及计算过程 |  |
| C-05 | 含税总价113万元、未税总价100万元、税额20万元 | 税额冲突，人工核对 | 税费条款、价款表和计算结果 |  |
| C-06 | 固定金额10万元，同时写“合同总价的10%”，合同总价120万元 | 固定金额优先（按当前默认），提示比例不一致 | 固定金额、比例、总价三处原文 |  |
| C-07 | 付款计划写“余款支付”，但没有前序阶段金额或余款计算方式 | 剩余金额无法计算，人工核对 | “余款”原文、全部阶段金额位置 |  |
| C-08 | 两处均写“最终付款”，一处为10万元、一处为20万元 | 重复阶段且金额冲突，人工核对 | 两处完整原文及位置 |  |
| C-09 | 金额均未标明币种 | 按开发默认人民币，同时提示采用默认值 | 金额原文和币种缺失检索证据 |  |
| C-10 | 只写“支付合同总价的30%”，合同总价缺失 | 比例分母缺失，相关金额判断无法完成；整体审核继续 | 比例原文、总价缺失范围 |  |
| C-11 | 付款条件位于未提供的“附件二” | 材料缺失，不能判断附件金额和阶段 | 正文附件引用、缺失材料清单 |  |

## 使用规则

1. 当前直接作为开发回归案例使用；后续可补充真实合同表达。
2. 正式金标和通过率另行建立，不影响当前产品开发。
3. 每个案例必须保存输入文本、预期状态、证据位置、人工处理动作和复核人。
4. 当前不设漏报率、误报率阈值；待案例确认后再单独批准。
