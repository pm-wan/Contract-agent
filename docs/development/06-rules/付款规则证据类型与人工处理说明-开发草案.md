# 付款规则证据类型与人工处理说明（开发阶段已确认）

## 一、证据类型候选枚举

| 编号 | 中文证据类型 | 典型内容 | 用户确认/补充 |
|---|---|---|---|
| E-01 | 合同正文价款条款 | 总价、税额、币种、付款条件 |  |
| E-02 | 价款/报价/清单表 | 行项目、数量、单价、合计 |  |
| E-03 | 付款计划表 | 阶段、比例、固定金额、触发条件 |  |
| E-04 | 税费和发票条款 | 税率、含税/未税、发票条件 |  |
| E-05 | 附件报价或技术协议 | 附件金额、版本、适用范围 |  |
| E-06 | 补充协议/变更协议 | 变更金额、替代关系、签署日期 |  |
| E-07 | 采购订单/订单确认 | 订单金额和订单优先级 |  |
| E-08 | 交付、验收和结算条款 | 阶段完成和付款触发证据 |  |
| E-09 | 材料缺失证据 | 未提供的附件、扫描缺页、不可读页 |  |
| E-10 | 冲突位置证据 | 正文与表格或不同版本的全部原文 |  |
| E-11 | 解析质量证据 | OCR失败、页码缺失、文本截断 |  |

## 二、什么情况下不能形成“有证据结论”

- 直接说“币种为人民币”，但原文没有金额附近的币种证据，也没有明确记录“采用默认人民币”。
- 直接说“没有付款条款”，但附件、补充协议或扫描页尚未完整检索。
- 用百分比计算付款金额，却没有引用比例分母。
- 只展示一个冲突位置，隐藏另一个金额或版本。
- OCR或解析不完整，却把未识别内容当作不存在。
- 计算结果依赖未批准的企业制度或未复核的法律材料。
- 输出“通过/不通过”但没有原文、位置和计算过程。

以上情况只能输出“需人工核对”，不得输出确定性结论。

## 三、待确认概念

- **剩余金额（residual）**：已明确阶段金额扣除后尚未分配的余额。它不是自动生成的付款阶段；是否允许作为尾款、使用何种分母和四舍五入规则，需业务确认。
- **任一/全部（any/all）**：当一个付款条件包含多个阶段时，“任一”表示满足其中一个即可，“全部”表示每个阶段都必须满足。系统不应擅自推断，须在规则中明确。
- **重复阶段**：同名或同触发条件出现多次。金额和条件相同可标记重复；金额、时间或条件不同应标记冲突并人工核对，不自动合并。

## 四、统一人工处理输出

人工处理任务至少包含：问题类型、受影响字段、全部原文证据、缺失材料、冲突说明、建议补充材料、处理人、处理结论、处理时间和复核人。人工未完成时，其他有证据的合同检查继续执行。
