# 规则生产升级前置清单

> 状态：未批准、未满足生产发布条件的执行清单。当前价款与付款规则均为开发态；不得将本清单、开发评测通过率或哈希报告解释为批准或发布。

## 执行原则

- 每项由指定责任角色提供可追溯证据并由独立复核者确认；责任人、来源或批准缺失时保持未完成，不以合成样本、工程测试或口头确认代替。
- 规则、知识、评测和阈值按不可变版本绑定。任何输入版本变化都要求重新评测和审批；不得修改已审批产物后沿用原批准。
- 所有必需项完成后仍须由授权发布负责人执行正式 Go/No-Go；`release_ready` 或一致性校验本身不是签署或发布授权。

## 必需清单

| 项目 | 责任角色 | 必须留存的证据 | 未完成时 |
|---|---|---|---|
| 法律依据 | 法务/领域负责人 | 适用法域和合同范围；经授权的法律正文或权威来源、版本/效力时间、来源 SHA-256、解释与适用边界；逐条规则引用映射 | 不得声称规则具有法律依据或适用于生产 |
| 企业制度 | 企业知识负责人/业务负责人 | 经批准的制度原文、制度版本和适用组织/业务范围、来源哈希、与法律依据的优先关系及冲突处置 | 不得形成企业政策判断 |
| 规则与 Skill | 规则维护人、领域批准人 | Rule/Skill 精确版本及哈希；槽位定义、依赖、数值/单位边界、失败关闭策略；书面审批人、审批时间、批准范围 | 保持开发态，不发布规则 |
| 独立金标集 | 独立 Evaluator/QA 与法务/业务裁决人 | 不由规则作者或开发 fixture 派生的真实授权样本；正反例、缺材料、冲突、边界、安全类别；脱敏/授权记录、样例来源和哈希、逐例裁决与证据定位 | 不得把开发 observations 当成准确率证据 |
| 阈值与发布门 | QA、法务/业务负责人 | 事先版本化批准的指标定义、分母、分层阈值、严重漏报/错误通过口径、置信区间或样本量要求、审批身份与时间 | 评测状态继续 `blocked_no_approved_thresholds` |
| 实际运行评测 | 独立 Evaluator/QA | 固定模型/提示/工具/规则版本，在独立集上的原始 Worker observations、失败案例和重跑记录；绑定 suite、fixture、输入、规则、环境和报告哈希 | 合成回归结果仅供工程回归 |
| 证据与人工流程 | 产品/领域负责人、安全负责人 | 引用定位与来源授权验收；高风险结果人工队列、审计、补料、幂等和权限验收；确认哪些动作不构成自动批准 | 不得自动确认或清除 blocker |
| 运行与安全 | SRE/安全负责人 | 执行预算、超时/重试/限流；密钥与访问控制；数据保留/删除；告警、备份恢复、灾备、漏洞和隐私评审记录 | 不得进入生产流量 |
| 发布与回滚 | 发布负责人/Operator | 发布包清单及哈希、目标环境、灰度/监控/停止条件、回滚目标和演练记录；Go/No-Go 会议结论与签署 | 不得发布或扩大流量 |

## 当前状态

- 本仓库价款开发评测套件包含人工编制的合成 observations；不是独立金标，也不是实时 Worker/模型输出。
- 评测报告的 SHA-256 只用于一致性核验，不是数字签名、可信构建证明或审批记录。
- 当前无已批准的正式阈值、独立真实金标及完整发布签署；规则发布审计必须保持 `release_ready=false`。

## 解除阻断的审计记录

每轮审计记录清单版本、项目、证据文件及 SHA-256、责任人与复核人、批准时间、适用规则版本、未决事项和结论。缺少任一必需记录时，结论为“不具备生产发布条件”；不得从 `blocked` 推断业务批准。
