# 法律知识库字段与关联设计（开发草案）

> 状态：**开发阶段已确认**。法律依据是规则依据，不等于规则本身。以下字段直接用于产品建模，正式法律材料后续按同一结构替换。

## 一、核心实体

### 1. 法律来源

`source_id`、来源名称、来源类型（法律/行政法规/部门规章/司法解释/规范性文件）、发布机关、适用法域、官方发布地址或公报编号、权威等级、原始文件存储地址、语言、创建人、创建时间。

### 2. 法律版本

`legal_version_id`、`source_id`、版本名称、公布日期、施行日期、失效日期、状态（候选/生效/失效/撤回）、完整原文哈希、文件格式和大小、获取时间、替代的版本、发布依据、备注。

### 3. 条款

`provision_id`、`legal_version_id`、章/节/条/款/项/目编号、标题、原文、规范化文本、文本哈希、稳定引用标识、适用主题、适用地域、有效起止时间。

### 4. 法律引用

`citation_id`、`provision_id`、引用目的（规则依据/解释/例外）、引用原文、原文位置、引用文本哈希、引用者、复核者、复核时间、复核结论。

### 5. 复核与批准记录

复核记录包含：记录编号、对象类型和版本、复核人、复核角色、复核结论、问题清单、复核时间、记录哈希。批准记录包含：批准编号、批准人、批准角色、批准动作、批准时间、适用环境、意见、记录哈希。

### 6. 规则绑定

`binding_id`、规则名称和规则版本、法律版本、条款范围、绑定用途、必需/可选、适用条件、绑定状态、绑定快照哈希、创建人、复核人、批准记录编号。

## 二、关联关系

- 一个法律来源可以有多个法律版本；一个法律版本包含多个条款。
- 一个条款可以被多个法律引用使用；每次引用保留独立位置和哈希。
- 一个规则版本可以绑定多个法律版本和条款；法律版本更新不得覆盖原绑定，必须生成新绑定快照。
- 法律依据与企业付款立场分开建模；二者通过规则版本上的不同引用关系关联，不互相冒充。
- 失效、撤回和替代均保留历史记录，不物理删除原文和审批记录。

## 三、最小控制要求

1. 任何生效法律版本必须有原文哈希、发布机关、公布/施行/失效日期和稳定引用。
2. 规则只能引用已复核的条款；未复核材料只能进入候选状态。
3. 原文变更、来源地址变化或哈希变化必须创建新版本并重新复核。
4. 规则输出只引用法律条款，不把法律条款直接当成付款结论。
