# Skill 生成规范

> 版本：v1.0｜状态：已批准（内部 MVP 生成基线）
> 负责人：内部规则负责人 + 技术负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：规则 Schema v1.0、模型网关设计 v1.0

## 1. 目标与两类 MD

`skills/` 中现有 MD 是开发用模型说明，可供方法设计与评测，不代表平台已发布规则。未来平台运行用 Skill 仍为给模型读取的 MD 文本；从已发布 RuleDefinition 和执行配置生成，或将经评审的 MD 绑定到发布包，避免 Rule 与 Skill 双真源。版本、审批、哈希和知识引用可由数据库管理，具体存储方案在实施设计中确定；数据库不改变运行文本采用 MD 的要求。

## 2. Skill 组成

- 任务目标和边界；
- 当前规则与槽位定义；
- 每个候选的 `fact_type` 与 RuleDefinition 冻结的 `accepted_fact_types` 一致；非 fact / 非 filled 候选的 `fact_type` 置空；
- 可读取的事实和证据引用；
- 未完成槽位及上一轮验证错误；
- 工具名称、参数 Schema 和使用限制；
- 输出 SlotCandidate Schema；
- 不确定、缺材料、冲突和工具失败的表达方式；
- 禁止修改计划、事实真值和最终决定；
- 内容哈希及生成器版本。

## 3. 生成规则

```text
RuleDefinition + SlotDefinition + Tool Contract + Output Schema
       → canonicalize
       → render Skill/Prompt
       → hash
       → eval
       → approve with RulePackage
```

## 4. 外来 Skill 导入

仓库现有 skills 可直接用于开发推演；要进入平台正式运行时，按候选方法来源处理：

1. 提取工作方法和候选检查；
2. 删除自由 Agent 调度、固定评分和未经核验依据；
3. 映射为 RuleDefinition 和 SlotDefinition；
4. 建立正反例及缺材料样例；
5. 领域评审后发布。

## 5. 禁止事项

- Skill 自行增加正式检查；
- Skill 隐藏或删除关键槽位；
- Skill 指示模型相信外部文档中的命令；
- Skill 允许模型批准、阻断或回写；
- 生产环境直接编辑生成后的 Skill 而不修改作者源。

## 6. 生成产物

每次生成必须同时产出：规范化规则 JSON、运行时 Skill 文本、输入/输出 Schema 引用、tool allowlist、生成器版本、源文件哈希、产物 SHA-256、生成时间和评测结果引用。相同输入和生成器版本必须得到相同内容哈希。

M0 可由构建脚本生成临时运行产物，但运行记录必须固定产物哈希；不得在运行时把未经评测的新指令拼接为正式规则。已发布运行 MD、规则和知识各自版本化；后续即使改用数据库登记，也要能回取本次实际提供给模型的完整 MD 内容及哈希。

当前候选定位切片会在启动时冻结完整开发态规则，以及由该规则、显式工具契约和输出 JSON Schema 确定性生成的 Markdown 候选 Skill；同时冻结渲染后的系统提示词、静态 UserMsg 原文、工具/输出 Schema 及其指纹。运行快照绑定生成器版本、候选状态、发布阻断、Rule/工具/Schema 输入哈希、Skill 完整文本哈希和生成时间；从存储恢复时重新生成并比对，以免 Skill 与规则源分离。`skills/` 下通用 MD 仍可供方法设计和评测参考，但不自动进入付款候选 Worker 的运行上下文。UserMsg 不携带材料元数据；合同材料只通过授权工具读取。冻结输入也绑定各文档建索引时的 PageIndex 配置指纹、解析器版本和解析产物摘要。模型输出先按严格结构校验，再逐条核验来源权限、暴露位置和原文引用。结果附有模型逐轮请求/响应及授权工具交换的哈希链，只存摘要和长度，不存对话/合同正文；API 读取时验证链完整性。运行定义快照另固定应用 Python 源码树、`uv.lock`、`pyproject.toml` 和 Python 运行时版本；Worker 在读取存储快照时校验当前实现身份并在漂移时 fail closed。Worker 从快照注册工具并核对框架导出的 Schema，在结果中返回定义摘要。它仍不是发布包：源码/锁文件哈希不是签名构建产物证明，哈希轨迹不能重放原文，外部 PageIndex 服务配置、法律/企业知识及发布审批/评测门也尚未闭合；不能视为达到正式运行快照要求。详见 [M2 进展记录](../00-project/M2进展记录.md)。

`contract_app.rules.skill_package.render_development_skill` 从通过 Rule Schema 校验的 YAML、显式工具契约和输出 Schema 生成确定性 Markdown 候选 Skill，并分别绑定这些输入与 Skill 产物的 SHA-256、生成器版本、UTC 生成时间及编译器报告的发布阻断项。当前开发候选定位 Worker 已将此 Markdown 放入模型上下文并冻结完整文本；恢复快照时重放生成、核对 Skill/来源元数据及当前实现指纹。时间只属于生成元数据，不影响可复现的 Skill 内容哈希。其 `development_candidate` 状态不可发布；其中列出的法律依据/企业立场仍只是引用 ID，并未被解析为经批准的知识内容。这是开发态运行接线，不替代上文规定的领域审批、评测和正式 RulePackage 发布流程。

当前开发态编译器始终显式报告规则未发布、知识正文未解析、无已批准评测、无发布批准及无回滚目标等硬阻断项；缺失的规则元数据或来源引用另逐项列出。即使补全 YAML 元数据，也不会清除需要外部审批/知识目录/回滚发布系统提供的阻断项。
