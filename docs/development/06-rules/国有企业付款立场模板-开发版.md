## 二、角色中文含义与当前代码逻辑

| 英文角色 | 中文名称 | 职责 | 当前实现情况 |
|---|---|---|---|
| Author | 编制人/起草人 | 编写规则、政策和样例 | 当前代码只保存规则/引用，不保存正式人员名册 |
| Reviewer | 复核人 | 复核业务逻辑、法律依据和企业立场 | 发布生命周期校验角色分离；尚未接入持久化审批表 |
| Evaluator | 独立评测人 | 使用独立金标执行评测 | 已有开发态评测文件，尚未形成正式金标批准记录 |
| Approver | 批准人 | 批准进入 test/mvp 或批准制度生效 | 当前仅做生命周期校验，不代表已有批准 |
| Operator | 发布/运维执行人 | 发布、暂停、撤回、回滚 | 已有转换校验；尚未开放正式发布入口 |

当前仓库的 `enterprise.payment-policy/mvp-v1` 仍是引用名；开发阶段允许产品使用开发默认口径，但不得对外宣称为已批准正文。

## 三、付款立场待确认条款

| 主题 | 开发阶段建议 | 企业确认/修改 |
|---|---|---|
| 预付款 | 原则上与履约保障、审批和发票条件绑定 |  |
| 进度款 | 以合同总价为默认分母，按验收/交付证据付款 |  |
| 尾款 | 保留质保金、缺陷责任或最终验收条件 |  |
| 发票 | 付款前校验发票类型、金额和税率是否匹配 |  |
| 履约保障 | 高预付款或高风险合同要求保函/保证金 |  |
| 价款冲突 | 正文、价款表、附件和补充协议全部展示，不能静默覆盖 |  |
| 高风险结论 | 由人决定是否通过，系统只提示证据和风险 |  |
| 变更协议 | 核对编号、签署日期、适用范围和是否替代原金额 |  |

## 四、修订、批准和撤回

正式版必须记录：制度原文、上传确认、内容哈希、编制人、复核人、批准人、批准时间、适用范围、生效/失效日期、发布版本、暂停/撤回原因和回滚目标。开发版不得直接进入正式审核或发布。
