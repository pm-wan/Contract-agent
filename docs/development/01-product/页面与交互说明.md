# 页面与交互说明

> 版本：v1.1 候选｜状态：按新 MVP 流程修订中
> 负责人：内部产品负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：PRD v1.1、用户故事与验收标准 v1.0

## 1. 信息架构

| 页面 | 核心内容 | 关键动作 |
|---|---|---|
| 案件列表 | 状态、合同、对方、负责人、风险和待办 | 新建、筛选、进入案件 |
| 主体纠错队列/纠错页 | 租户内已确认主体案件的最小纠错上下文 | 主体管理员搜索案件、核对当前 UUID/版本、填写新 UUID 和依据并确认后果；不开放案件材料/结果，也不授予成员身份 |
| 案件工作台 | 版本、用途、运行、覆盖和决定 | 启动、取消、重审、导出 |
| 材料与解析 | 文件、附件、页、条款、异常 | 补材料、确认审查版本 |
| 事实与冲突 | 候选值、来源、时点和冲突 | 确认、驳回、转人工 |
| 审查结果 | 发现、证据、依据、限制和行动 | 复核、提出修改、上报 |
| 人工任务 | 补材料、复核、审批和截止时间 | 领取、处理、退回 |
| 版本与重审 | 差异、失效结果和重算范围 | 确认新运行 |
| 报告与决定 | 结构化结论、限制和决定 | 批准、例外、整改、导出 |
| 审核准备 | 待审文件、主体确认、历史合同候选、项目客户合同、来源状态 | 审核人确认主体、选择合同、查询来源、预览并冻结；确认后主体锁定，普通审核人不能直接更改。租户主体管理员可在任意准备/审查阶段纠错并留审计；纠错撤销现有选择与材料授权、使旧案件版本及运行不能继续作为当前审查，旧快照和运行保留作历史且不原地改写。原主体下的材料版本保持不可变；新审查需在更正主体范围下上传新材料版本，再重新选择/授权/预览/冻结 |
| 上下游比对 | 14 类义务、双方原文和覆盖状态 | 查看双边条款、复核适用性、补充材料 |

## 2. 结果卡片最小内容

- 规则名称和版本；
- 审查对象；
- 判断状态和风险；
- 合同原文或数据事实；
- 规范/制度依据；
- 数据覆盖和限制；
- 建议动作；
- 是否需要具名审批；
- 结果及证据版本。

## 3. 交互原则

- 不用颜色作为唯一状态信号；
- “未找到”必须说明检查范围和解析完整性；
- 任何数字同时展示币种、单位、口径和截止日；
- 人工确认前展示对下游结果的影响；
- 高权限操作二次确认并展示不可逆影响；
- 页面不得用自由文本覆盖结构化结论。
- 历史合同候选按已确认主体查询并分页；列表和摘要不得显示金额或可稳定反推金额的信息。用户选择客户/历史合同时，分别显示“用于背景”或“用于上下游分析”的用途；无权选择时说明原因，服务端仍独立校验。
- 预览页列出每个来源的查询范围、时间、完整性和未启用/无权限/空结果/部分/失败/过期状态。冻结前明确本次会纳入哪些合同；冻结后更新材料或来源产生新版本。
- 结果页以“合同审核发现”“签约决策参考”“审核范围与数据提示”三组呈现。上下游项可并排定位双方条款；无客户合同时只说明本次未执行上下游分析，不把它当成合同缺陷。
- 页面、报告和导出使用同一服务端授权结果；金额遮挡不能仅由前端完成。权限变化后刷新可见内容，直达无权限页面给出明确拒绝及返回路径。
- 合同候选查询和财务查询均有加载、空、部分、失败、超时和重试状态；旧响应不得覆盖用户新选择，冻结操作防重复提交。

## 4. 空态与异常态

必须设计：未上传、解析中、解析失败、缺附件、无权限、接口不支持、部分返回、模型超时、等待人工、结果过期和版本已替换。

## 5. 待产物

- 页面线框图；
- 字段级可见性矩阵；
- SSE/轮询行为；
- 报告打印样式；
- 无障碍和浏览器兼容范围。

上述待产物不改变页面职责和后端权限边界；其中字段级可见性矩阵必须在 M2 前完成，其余在对应页面实现前完成。

## 6. M0 最小页面

M0 只实现四个可用路由：案件列表/新建、案件工作台、运行结果、人工任务。材料解析和证据定位可在案件工作台内以面板呈现。所有路由必须实现加载、空、失败、无权限和过期版本状态。
