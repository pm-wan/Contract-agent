# 业务流程与状态机

> 版本：v1.1 候选｜状态：按新 MVP 流程修订中
> 负责人：内部产品负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：PRD v1.1、MVP 基线确认记录

## 1. 主流程

```text
创建案件
 → 上传主合同/附件并解析
 → 提取并确认主体
 → 查询和选择曾签历史合同；按需选择/上传项目客户合同
 → 查询已启用且获授权的财务/外部来源
 → 预览来源、时间、完整性与权限；固定 InputSnapshot / FactSetSnapshot
 → 类型识别并编译 AuditPlanSnapshot
 → 执行通用/专项检查及适用的 14 类上下游比对
 → 证据与结论门禁
 → 人工任务或完成
 → DecisionSnapshot
 → 三类结果与报告/Mock Delivery（默认关闭）
```

## 2. AuditCase 状态

| 状态 | 含义 | 可进入 |
|---|---|---|
| draft | 案件已创建，材料未确认 | ready, cancelled |
| ready | 材料满足启动条件 | running, cancelled |
| running | 至少一个运行正在执行 | waiting, reviewed, cancelled |
| waiting | 等待材料、数据或人工 | running, cancelled |
| reviewed | 已形成完整结构化结果 | decided |
| decided | 有权人员已作决定 | closed, running |
| closed | 案件归档 | running（显式复核） |
| cancelled | 本次案件取消 | 无；复用需新建案件 |

## 3. AuditRun 执行状态

`queued → running → waiting_material / waiting_data / waiting_human → running → completed`

异常分支：`retryable_failed → queued`、`failed`、`cancelled`、`superseded`。

允许转换：

| 当前状态 | 允许进入 | 必须满足 |
|---|---|---|
| queued | running, cancelled, superseded | 获得有效 lease 或收到取消/替换命令 |
| running | waiting_material, waiting_data, waiting_human, retryable_failed, failed, completed, cancelled, superseded | 提交时 fencing token 仍有效 |
| waiting_material | queued, cancelled, superseded | 新材料形成 InputSnapshot 修订 |
| waiting_data | queued, cancelled, superseded | 数据可用或人工选择受限继续 |
| waiting_human | queued, cancelled, superseded | HumanTask 已作有效决定 |
| retryable_failed | queued, failed, cancelled, superseded | 未超过次数、时间和成本预算 |
| completed | 无 | 重审创建新 AuditRun |
| failed | 无 | 恢复或重审创建新 AuditRun |
| cancelled | 无 | 不允许复活 |
| superseded | 无 | 不允许对外投递 |

执行状态不得承载“通过/失败”的专业含义。

未选客户合同时，常规采购审核继续并说明本次未做上下游分析。已启用来源超时或失败时，依赖该来源的检查进入受限状态，不把整案自动阻断；材料或来源需要更新时生成新快照和新运行。

## 4. 检查判断状态

- `passed`
- `issue_found`
- `needs_material`
- `undetermined`
- `not_applicable`
- `human_review`

## 5. 关键事件

- `case.created`
- `document.version_added`
- `input.snapshot_frozen`
- `audit.plan_compiled`
- `check.completed`
- `human_task.created`
- `fact.conflict_resolved`
- `result.invalidated`
- `audit.run_completed`
- `decision.recorded`
- `integration.delivery_requested`

事件只表示已提交的业务事实；模型流式 token 不作为业务事件。

## 6. 版本变化

新材料、人工纠正、数据刷新、规则或规范变化不得修改旧运行。系统创建新输入修订或新运行，通过 ResultDependency 计算失效范围，并保留旧报告可回放。

## 7. 完成与失败语义

- `completed` 只表示计划内检查均达到允许的执行终态，不代表合同通过；
- `failed`、`retryable_failed`、等待态和未解决关键冲突均不得映射为 `passed`；
- 关键检查缺失时，运行不得进入 `completed`；
- AuditCase 的 `reviewed` 必须引用一个已完成且未被替换的 AuditRun；
- 最终决定只写入 DecisionSnapshot，不覆盖 CheckResult；
- Mock Delivery 只能发送当前、未取消、未替换且已授权的结果。

## 8. 并发与幂等

- 所有状态命令携带对象 `version`，版本不匹配返回冲突；
- 启动运行使用 `tenant_id + case_id + idempotency_key` 去重；
- 同一案件可保留多个历史运行，但同一输入修订只允许一个 active run；
- 任务提交必须同时校验 lease、fencing token、取消标记和 superseded 标记。
