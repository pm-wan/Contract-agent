# 用户故事与验收标准

> 版本：v1.1 候选｜状态：按新 MVP 流程修订中
> 负责人：内部产品负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：PRD v1.1、业务流程与状态机 v1.0

## US-01 创建案件

作为业务提交人，我希望上传合同并创建审查案件，以便获得针对固定版本的审查结果。

验收标准：

- 系统生成唯一 case_id 和 document_version_id；
- 相同文件可在不同用途或轮次创建独立运行；
- 文件不可读时明确失败原因，不启动正式检查；
- 原件不被覆盖。

## US-02 固定审计计划

作为法务审查人，我希望看到本次必须执行的检查，以便确认不存在模型自行漏项。

验收标准：

- 启动运行前生成不可变 AuditPlanSnapshot；
- 展示适用和不适用检查及其依据；
- 运行中 Agent 不能删除关键检查；
- 规则变化不静默改变已启动运行。

## US-03 查看证据

作为审查人，我希望从发现直接定位到合同原文或来源记录。

验收标准：

- 引文属于本次固定文档版本；
- 页码、条款、表格或记录位置可回看；
- 引文不匹配时结果进入复核而不是继续发布；
- 模型推理本身不被标成证据。

## US-04 补材料

作为业务提交人，我希望知道缺少什么材料以及为什么需要，以便定向补充。

验收标准：

- 生成具名 HumanTask；
- 说明缺失材料影响的检查和结论；
- 补充材料形成新版本或输入修订；
- 仅重审受影响结果。

## US-05 事实冲突

作为领域复核人，我希望比较冲突来源并记录确认理由。

验收标准：

- 不覆盖任一原始候选；
- 记录确认人、理由、时间和适用范围；
- 未解决冲突不得自动通过依赖检查；
- 确认后依赖节点正确失效并重算。

## US-06 人工决定

作为审批人，我希望在授权范围内接受、整改、例外或阻断。

验收标准：

- 校验审批人角色和金额/事项权限；
- 决定绑定固定结果版本；
- 原发现保留；
- 例外包含理由、范围和有效期。

## US-07 系统故障

作为合同管理员，我希望审计系统故障不会产生错误通过或错误投递。

验收标准：

- 执行失败与专业通过分离；
- Mock 回调重复不会产生重复投递；
- 过期版本结果不得生成有效投递；
- 故障采用 fail-safe：保留失败状态并转人工，不输出通过。

## US-08 查询运行与进度

作为审查人，我希望刷新页面或断线重连后仍能看到一致进度。

验收标准：

- 查询接口返回稳定的执行状态、版本和最近业务事件；
- SSE 断线可使用事件 ID 续传；
- 流式 token 不作为业务进度；
- 最终状态以查询接口为准。

## US-09 取消与版本替换

作为审查人，我希望取消错误运行或在合同换版后停止旧运行。

验收标准：

- 取消是幂等命令；
- Worker 提交前重新检查取消和 superseded；
- 已提交的历史证据和结果保留；
- 新版本创建新运行，旧结果不被覆盖。

## US-10 确认主体与选择合同

作为审查人，我希望确认签约主体并选择与本次审核相关的历史或客户合同。

验收标准：只查询同一已确认主体的曾签历史合同；候选无金额；选择时说明背景或项目上下游用途；用户无权读取的合同不进入冻结输入；未选客户合同时常规审查仍可完成。

## US-11 查询来源并冻结

作为审查人，我希望在运行前看到财务、合同及外部来源的范围、时间和可用状态。

验收标准：未启用、无权限、空、部分、失败、过期分别呈现；刷新数据产生新快照；MVP 后半段真实财务与合同 API 联调通过，模拟结果不计为真实接入。

## US-12 查看上下游与三类结果

作为审查人，我希望看到客户合同义务如何被采购合同覆盖，并区分合同问题、签约背景和审查限制。

验收标准：14 类逐项可回看双方原文，区分五种覆盖状态与材料不可用；三类结果在页面、报告和导出一致；金额按服务端当前权限过滤。
