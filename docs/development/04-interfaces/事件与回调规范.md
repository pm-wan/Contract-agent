# 事件与回调规范

> 版本：v1.0｜状态：已批准（MVP 内部事件与 Mock Delivery）  
> 负责人：内部技术负责人  
> 批准人：内部项目发起人  
> 适用阶段：M0～M4  
> 上游依据：业务流程与状态机 v1.0、持久工作流设计 v1.0

## 1. 事件封装

```json
{
  "event_id": "uuid",
  "event_type": "audit.run_completed",
  "event_version": 1,
  "tenant_id": "uuid",
  "case_id": "uuid",
  "run_id": "uuid",
  "sequence": 42,
  "occurred_at": "RFC3339",
  "payload": {},
  "trace_id": "string"
}
```

## 2. 顺序与续传

案件内 sequence 原子分配；客户端携带 last_event_id/sequence 续传。不得用并发 `max(sequence)+1`。

## 3. Outbox

业务提交和 outbox 同事务。发送至少一次，消费者按 event_id 幂等。失败进入有限重试和死信处置。

## 4. 回调安全

- 仅允许登记目标；
- 双向 TLS 或签名认证；
- 时间戳、nonce 和防重放；
- 不在 URL 传递敏感数据；
- 回调响应不改变已提交业务事实；
- 保留发送、响应和最终处置记录。

MVP 不配置真实回调目标。上述安全要求用于 Mock Delivery 测试和未来连接器验收；任何真实目标启用均构成范围变更。

## 5. 事件版本与兼容

- event_type 表示语义，event_version 表示 payload 版本；
- 新增可选字段保持同一版本，删除、改名或改变语义必须升版本；
- 消费者忽略未知可选字段，拒绝未知 event_version；
- SSE event id 使用 event_id，data 使用事件封装 JSON；
- outbox 清理前必须确认发布状态及审计保留要求。
