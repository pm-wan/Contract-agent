# 合同系统接入规范

> 版本：v0.2｜状态：MVP 后半段详细设计草案

## 1. 首期能力

真实只读合同查询属于本轮 MVP。前半段用模拟来源验证选择、授权和快照流程；后半段结合实际合同系统完成详细接口设计、联调和验收。正式审批回写不在本轮。

- 按已确认的签约主体查询曾签历史合同候选，返回标题、类型、签署时间、状态和无金额的合作事项摘要；同集团其他法人不自动扩展；
- 在用户选择且逐份授权后，读取固定历史合同版本作为背景；用户明确关联项目时才用于上下游分析；
- 在用户选择且授权后，读取项目客户合同固定版本，或接受用户上传，用于 14 类上下游义务比对；
- 记录选择人、同一我方法人校验、用途、授权结果、双方文档版本和原文定位；
- 读取本次待审合同及附件的固定版本（如入口由合同系统提供）。

## 2. ExternalBinding

只读查询至少绑定 tenant_id、source_system_id、external_contract_id、external_document_version、用途、授权范围和内容哈希。workflow_instance_id、node_instance_id、approval_round、source_request_id 仅在未来审批节点集成时需要，不作为当前只读查询前置条件。

## 3. 幂等

只读查询以来源合同 ID、版本和查询条件识别固定结果；同一版本内容哈希变化应报冲突。未来节点调用再使用 `tenant + source_system + source_request_id` 幂等。

## 4. 版本

所选合同版本或附件变化时生成新上下文版本并标记受影响旧结果；未来若有回写，回写前再校验源版本和节点轮次。

## 5. 查询完整性

历史合同查询返回 query_scope、分页状态、截断标记、权限范围和总数（如支持）。Top-K 结果不得表述为“全部历史合同”。候选列表和自动摘要不得包含金额或可稳定反推出金额的信息；全文读取、模型输入与结果按当前用途和字段权限重新校验。

## 6. 回写

回写默认关闭。启用后使用登记目标、签名、防重放、幂等 result_id、有限重试和 outbox。审计完成不等于节点批准。
