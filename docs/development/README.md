> 文档集版本：v0.4 修订中

> 当前阶段：按 2026-09-24 目标方案重建 MVP 契约

## 1. 文档体系用途

本目录把 `docs/六领域合同审计方案` 中的方案设计转化为可决策、可开发、可测试、可验收和可运维的正式工程文档。

[9 月 24 日目标方案](../整体方案设计指导与实现层级架构.md)规定本轮 MVP 的业务范围；本目录逐步补齐需求、接口、数据和验收契约。2026-09-17 的旧批准文件保留历史追溯，但其中 fixture-only、真实接入延期、10 周和旧样本指标不再作为本轮范围依据。修订中的文件待负责人评审后成为新开发基线。

## 2. 文档状态

| 状态 | 含义 | 是否可作为开发基线 |
|---|---|---:|
| 草案 | 已形成初稿，仍可结构性调整 | 否 |
| 待评审 | 内容完整，等待领域负责人评审 | 否 |
| 已批准 | 负责人已确认，纳入版本基线 | 是 |

每份文档页首应包含：版本、状态、负责人、批准人、适用阶段、上游依据和变更记录。

## 5. 变更控制

已批准或已冻结文档发生变更时，提交变更记录，至少说明：

- 变更原因和业务价值；
- 影响的需求、接口、数据、规则、测试和运行版本；
- 是否导致既有结果失效或历史案件重审；
- 回滚方式；
- 产品、领域和技术批准人。

架构取舍使用 ADR；接口使用版本化契约；规则使用稳定 `rule_id + version`；运行结果永远绑定原基线，不被新版本静默改写。

本轮目标范围见 [MVP 基线修订记录](00-project/MVP基线确认记录.md)；工期和成本按[新实施计划](00-project/实施计划与里程碑.md)重估。真实财务/合同接口详细设计与联调在 MVP 后半段完成。

## 7. 当前开发许可

- 允许：M0 工程骨架、契约生成、数据库迁移、文档解析、持久任务、模型 mock、`legal.payment_conditions` 纵向闭环；
