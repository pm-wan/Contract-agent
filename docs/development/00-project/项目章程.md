# 项目章程

> 版本：v1.1 候选｜状态：按 9 月 24 日范围修订中
> 负责人：内部项目负责人
> 批准人：内部项目发起人
> 上游依据：`docs/六领域合同审计方案/正式建设蓝图.md`

## 1. 项目使命

建设一个以 AuditCase 为中心、证据可回溯、规则可治理、人工可接管的合同审计平台，为合同签署、变更、续签和事后复核提供结构化审查建议。

平台不替代有权审批人，不以模型回答直接推进合同流程。

## 2. 业务目标

1. 降低关键合同风险漏检；
2. 缩短标准合同的首轮审查时间；
3. 统一企业审查立场和审批路由；
4. 将合同、财务、历史关系和制度证据联结起来；
5. 形成可解释、可复核、可重审的审计记录。

## 3. 内部 MVP 目标

- 以采购方服务及软件采购主合同为首个审查场景，完成主体确认、历史合同选择、项目客户合同选择和分层审核；
- 完成 14 类客户合同向采购合同的义务传递分析及三类结果呈现；
- 在 MVP 后半段完成真实财务与合同系统只读接入，外部经营/信用信息排在末段；前半段以模拟来源验证流程；
- 支持证据回看、补材料、人工复核、版本变化和定向重审；
- 通过独立金标、安全、恢复和业务验收。

## 4. 成功标准

以 [验收方案](../07-quality/验收方案.md) 为准。项目级最低要求：

- 适用关键检查执行覆盖率 100%；
- 高风险结论必须有充分证据；
- 缺材料、无权限和执行失败不得被表达为通过；
- 跨租户、跨案件未授权读取为 0；
- 生产故障不得静默推进外部审批节点。

## 5. 项目边界

首期范围见 [首期范围说明书](首期范围说明书.md)。任何新增合同类型、连接器、自动写回、自动签署或租户脚本能力均需变更评审。

## 6. 治理机制

- 项目负责人：负责范围、资源、阶段门和风险；
- 产品负责人：负责 PRD、用户价值和验收场景；
- 法务 DRI：负责法律规则、依据、金标和结论门禁；
- 财务 DRI：负责财务字段、口径、样例和规则；
- 技术负责人：负责架构、非功能目标和交付质量；
- 安全负责人：负责数据、模型、连接器和上线安全；
- QA 负责人：负责测试策略、独立验收集和发布报告。

## 7. 重大假设

- 试点方能够提供合法授权的脱敏合同及接口样本；
- 首期模型调用方式满足数据驻留和保密要求；
- 法务与财务 DRI 能持续参与规则确认和争议裁决；
- 原合同管理系统保留最终流程决定权。

## 8. 重大风险

| 风险 | 影响 | 控制 |
|---|---|---|
| 试点范围迟迟不定 | 无法冻结模型、接口和排期 | G0 前必须签署范围 |
| 样本或接口不足 | 规则只能纸面设计 | Phase 0 不通过则不承诺后续工期 |
| 法律依据与企业立场混用 | 结论责任不清 | 分层建模、分别批准 |
| 模型结论无证据 | 无法正式使用 | 证据门禁和人工任务 |
| 外部系统版本漂移 | 错审、错回写 | 快照、幂等和版本校验 |
