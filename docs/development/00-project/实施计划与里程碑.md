## 3. M0 必须验证的关键假设

### 3.1 文档链路与 PageIndex

样本至少包含原生文本 PDF、长合同、扫描 PDF、混合文本/图像 PDF、含表格/页眉页脚的 PDF、DOCX。记录每个样本的解析错误、页码和字符定位准确率、OCR 置信度、表格完整性、PageIndex 命中质量、页/块引用回跳正确率、索引构建时间、内存/CPU、重建与删除结果。禁止只展示“回答看起来正确”而不核验来源位置。

### 3.2 AgentScope 与应用工作流

验证一个结构化抽取节点与一个受控检索工具：模型只能看到应用构造的授权投影；测试工具 allowlist、Schema 拒绝、取消/超时、重试预算、中断恢复、进程重启、框架升级影响。AgentScope session/checkpoint 丢失不能丢案件运行或人工任务。

### 3.3 任务与业务真源

PostgreSQL job table 测试至少覆盖 at-least-once、重复投递、lease 过期、fencing token、事务失败、outbox 重投、人工等待、取消、输入版本 superseded、Worker 滚动部署。框架或模型不得直接写业务表或改变审批状态。

### 3.4 前端技术选型

React + Ant Design 已确定。M0 仅需确定其余配套栈，并以“选择数据源并预览/冻结、打开证据原文定位、查看长表格与差异、处理中/失败/空结果状态”做交互原型。比较项包括团队已有能力、开发维护成本、可访问性、表格/文档组件成熟度、OpenAPI 客户端生成、自动化测试、浏览器支持和目标部署环境。形成配套决策记录后锁定前端工程与依赖。

### 3.5 权限闭环

以主合同、已授权项目客户合同、已选历史合同、未关联合同、撤权和跨租户材料构造拒绝用例；验证检索前过滤、模型输入投影、缓存/索引隔离、派生结果再授权、报告/导出和日志。跨合同材料不是默认加入上下文，必须由用户选择/系统关系与用途授权显式建立。

## 5. 迭代节奏与估算方法

当前不承诺日历周数。M0 完成后，按实际团队投入日（人日）、并行依赖和阶段门返工风险估算；每阶段将工作拆为 1～2 周可演示切片，双周复核范围与阻塞。重估至少列出开发、文档工程、规则/法务、QA/安全、真实系统对接的可用比例，不以“模型开发”一项掩盖领域治理和样本工作。

成本与性能基线按至少三档输入测量：合同页数、客户合同候选数、财务明细行数、启用来源、是否 OCR、PageIndex 冷/热索引、模型 profile。报告 P50/P95、解析/OCR/索引/模型分项耗时、重试率、单案 token/费用及并发资源。目标值由 M0/M4 数据和试点 SLA 共同确认。

## 6. 交付门禁与变更控制

- 阶段退出条件必须附链接到自动化测试、评测结果、演示记录或负责人签字；文档勾选不代替证据。
- 新来源/新工具先声明数据类别、用途、字段授权、保留、错误语义、预算和失败降级，再进入计划节点。
- 所有运行绑定不可变输入版本、授权版本、规则/Skill/知识/模型/解析器/PageIndex 配置版本；变更创建新运行，不覆盖旧结论。
- 优先级 P0 的授权泄漏、金额错误、引用错位、必审漏检或失败误判通过，任一未解决即阻断相应能力上线。
- 9 月 17 日旧计划的工期、单案成本、并发和范围门槛废止；若需保留历史比较，只作为旧基线并注明不适用。

## 7. Go/No-Go

只有 M5 所定义的安全、证据、14 类覆盖、真实来源、质量和恢复门槛全部通过，且目标试点环境完成部署/回滚演练，才可对本 MVP 范围作 Go。任何来源、合同类型或数据字段未通过验收时，必须在 UI、报告和交付说明中明确限制，不得将模拟、未授权或不完整信息标记为已审/无风险。
