## 1. 本轮 MVP 目标

1. 以中国大陆法下我方作为采购方/客户的服务及软件采购主合同签署前辅助审查为首个场景；直接上传待审主合同及签约时附件，不自动审批、签署、盖章或向真实审批流程回写。
2. 提取并由工作人员确认签约主体；按同一主体查询曾签历史合同，工作人员选择用于背景参考的记录。未明确关联项目的历史合同不得自动用作上下游分析。
3. 工作人员选择或上传同一我方法人项目的客户合同；系统自动识别上游义务并与采购合同条款比对，覆盖指导稿 §8.2 的 14 类，逐项给出适用性、双方原文位置及五种覆盖判断。
4. 查询本企业已启用且获授权的财务 API，取得主体级应收应付汇总、全部当前未结清和逾期交易、最近 12 个月已结清交易。字段、主体/往来和结清/逾期口径在后半段对接时由财务部门确认。
5. 外部主体信息核验为基础能力；经营和信用背景数据在 MVP 末段按选定服务及授权接入。未启用或不可用时保留来源状态，不编造结果。
6. 查询、选择和预览后冻结本次材料、关系、来源数据及状态；先识别类型，再运行通用和有覆盖的专项检查。类型不明继续通用检查；混合类型披露未覆盖部分。
7. 结果分别呈现合同审核发现、签约决策参考、审核范围与数据提示；保留证据、版本、人工复核和重审能力。

## 2. 分阶段设计与验收

- MVP 前半段：固定主流程、授权维度、来源状态、快照和结果类别，用模拟来源验证端到端链路；不要求此时完成真实 API 字段映射。
- MVP 后半段：按实际系统完成财务和合同只读接口设计、数据口径确认、联调、分页/授权/错误处理和真实接入验收；外部经营/信用数据在末段处理。
- 最终验收：真实来源接入与全部 14 类上下游分析、权限、降级和三类结果均达到[验收方案](../07-quality/验收方案.md)的门槛。模拟数据演示不能代替真实接入验收。

## 3. 不在本轮范围

- 补充协议作为待审对象；我方不同法人间的上下游义务映射；无人工选择的项目合同自动配对；跨合同复用的企业信用档案或综合评分。
- 真实审批流程回写、自动批准/签署/盖章、对外 SLA、全量扫描件高精度 OCR、公众服务。
- 运行中的 Skill 自行调用财务或合同系统；按需 Tool 查询属于后续设计。

## 4. 尚需确定的实施事实

实际财务/合同 API、数据责任人与授权样本、外部信息服务、模型配置及新负载下的工期和成本需在对应阶段确认。当前不能以旧 10 周或 30 元/单案视为新范围承诺。实现基线改由 ADR-004 的 Python 全栈模块化单体候选与应用持久工作流承载；须在 M0 完成 PageIndex、文档解析、AgentScope、权限和任务恢复 Spike 后接受或重评。
