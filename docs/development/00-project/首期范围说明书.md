# 首期范围说明书

> 版本：v2.0 候选｜状态：待评审
> 上游：[MVP 基线修订记录](MVP基线确认记录.md)、[9 月 24 日方案](../../整体方案设计指导与实现层级架构.md)

## 1. 场景与边界

本轮面向中国大陆法下我方作为采购方/客户的服务及软件采购主合同签署前辅助审查。待审对象为主合同和签约时随附材料；用户直接上传，不接正式审批节点。试点优先在单一我方法人范围实施；上下游比对不跨我方不同法人。

## 2. In Scope

- PDF/DOCX 文本材料、版本和条款定位；扫描件按解析质量降级；
- 主体提取与人工确认，同一签约主体的曾签历史合同候选检索和人工选择；
- 用户选择或上传项目客户合同，自动抽取并比对[方案 §8.2](../../整体方案设计指导与实现层级架构.md)列出的全部 14 类义务；
- 财务 API 的主体级应收应付汇总、当前未结清和逾期交易、最近 12 个月已结清交易；
- 已启用且获授权的外部主体信息核验；经营/信用背景在 MVP 末段按实际数据服务接入；
- 查询状态与来源时间、预览、冻结上下文、合同类型识别、通用与专项审查；
- 法律与企业知识及方法分层，结果证据、权限、人工任务、重审和审计记录；
- 合同审核发现、签约决策参考、审核范围与数据提示三类结果。

真实财务和合同接口在 MVP 后半段完成详细设计和联调，前半段通过模拟数据验证流程。此顺序不改变最终交付范围。

## 3. Out of Scope

- 补充协议作为待审对象；多层补充协议效力合并；我方不同法人间客户/采购合同义务映射；
- 自动从项目描述匹配客户合同、自动纳入同集团其他子公司合同；
- 综合财务/信用评分、跨合同复用的企业画像；
- 自动批准、签署、盖章、真实审批回写或对外 SLA；
- 审核运行中由 Skill 自行查询真实系统。

## 4. 验收口径

每项正式发现必须有可回看的证据或明确限制。14 类义务均需适用性、上下游位置、覆盖判断及材料不足路径；未选择上游合同时，常规采购审核仍可完成并说明未执行上下游分析。真实来源查询要区分未启用、无权限、无记录、部分返回、失败和过期。无金额权限用户不得通过模型输入的派生结果获得受限金额。

具体金标和性能指标按新负载重定，旧 12+3+1 规则包、10 周、30 元/单案不是本范围的验收上限或替代标准。
