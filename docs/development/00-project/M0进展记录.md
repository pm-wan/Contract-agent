CI 工作流位于 `.gitea/workflows/`，因为仓库远端是 Gitea。其执行需要仓库启用 Actions 且有兼容的 Runner；目前仅验证了配置解析及本地同等检查，没有远端运行记录。CI 数据库角色初始化脚本只接受 Gitea CI 环境和 `postgres` 服务主机，不能作为生产角色配置工具。

Worker 恢复测试使用合成 `echo` 任务和本地 PostgreSQL。它证明了应用租约、fencing 与进程恢复的底座，不证明真实文档处理或 AgentScope/PageIndex 处理器的中断恢复。长任务已有数据库心跳续租，取消/替换命令可撤销活跃租约；`AgentCallBoundary` 在 AgentScope 协作式异步回复上验证了 deadline、取消传播和工具预算，但不能强制停止阻塞中的同步 SDK 调用，需通过 Worker 子进程隔离及 fencing 保证提交安全。跨部署滚动升级仍未验证。`supersede_run` 只标记旧运行并保留历史结果，尚未创建绑定新版输入快照的新运行。

人工等待当前只验证 `fact_review → confirm_fact`：Worker 可持久释放租约，案件中未撤权且角色匹配的成员可记录理由并使任务重新排队；确认本身不生成专业通过结论。合成处理器在重启后从数据库查询该决定。M1 仍需为实际处理器提供固定输入/决定引用和权限投影，并实现补材料、审批、领取、金额授权及 API 契约；不能把此 Spike 当作完整 HumanTask 产品验收。

权限测试的管理端连接只用于合成 fixture 写入；日常 `contract_runtime` 对新增授权表只有读取权。`AuthorizedPageIndex` 通过当前成员、选择、用途/字段授权以及数据库绑定的索引 ID 取回材料，适合暴露给模型工具；直接使用底层 `PageIndexAdapter` 仍应限于受信内部索引流程。当前没有按字段生成脱敏索引，因此带受限金额的原文在无金额授权或任务不需要金额时整体拒绝，不以遮挡 UI 代替安全隔离。

`InputSnapshotStore` 当前只处理仓库合成合同来源：预览仅返回被选材料的可用状态，冻结时在可串行化事务内重算同一范围并比较版本/哈希；成功后以 runtime 角色只增不改的表保存文档版本及来源哈希。模型专用的 `AuthorizedPageIndex` 拒绝未绑定 `input_snapshot_id` 的读取；已绑定的检索同时要求快照成员资格和当前授权，撤权后不因历史快照继续可读。预览使用的 `AuthorizationProjector` 仍可查询当前授权而无需快照。`JobStore.create_bound_run` 及 M1 HTTP API 已将正式运行引用到同案件快照，要求当前案件版本、用途、金额范围、成员及全部冻结材料权限仍有效，重复幂等键返回同一运行，并原子创建首个任务；旧 `create_case_and_run` 仅限 M0 fixture。`contract_review` 真实处理器、结果投影/报告、重审创建仍待实现，并须防止绕过模型专用网关。财务与真实合同来源的查询、分页、完整性、时效和冻结协议仍按 M4 接口资料补充，不能把此 fixture 流程计为真实来源验收。

付款条件规则当前只接受 `approved_for_development` 输入。即使所有候选槽位都填满，执行器仍返回 `human_review`，因为企业立场未批准、最低风险策略和精确计算尚未闭环。规则文档中“正例预期 passed”是未来金标目标，不是当前自动化通过证据。`RuleRun` 的解析文档集合须由授权快照组装，本次测试仅使用合成文档，不能替代实际模型/真实材料验收。

`tests/test_m0_vertical_spike.py` 用同一份合成 PDF 字节贯穿解析、假 PageIndex 建索引、数据库选择和授权、AgentScope 确定性假模型的只读工具调用、候选引用的页/字符/哈希校验，以及撤权后检索和派生结果拒绝。该 Spike 本身没有覆盖 HTTP 上传入口；M1 上传切片另由 `tests/test_document_upload.py` 验证受信身份、租户内成员校验、幂等、原件上传与持久解析任务及“暂存、未选择、未授权”。解析 Worker 的租约重领和解析产物落盘已在 M1 集成测试覆盖；该能力仍不构成真实 PageIndex 树模型、真实模型抽取或人工评审验收，不能单独作为 G0 完整纵向验收。

OCR 当前走本地进程标准输入/输出，不写原文临时文件；依据 [Tesseract 命令行手册](https://github.com/tesseract-ocr/tesseract/blob/main/doc/tesseract.1.asc)解析逐词 TSV 置信度与坐标。本机没有 Tesseract 可执行文件及语言数据，因此仅用假引擎/假 TSV 验证适配协议和降级；`ocr_requires_review`、`ocr_low_confidence` 和混合页 `has_images_unverified` 告警阻止将解析覆盖率默认为完整。OCR 引擎二进制/语言模型版本及实际合同识别准确率仍需在目标环境和脱敏样本上记录。

观测基线通过 [OpenTelemetry Python 手动插桩规范](https://opentelemetry.io/docs/languages/python/instrumentation/)实现。只跨任务/事件保存 W3C `traceparent`，不保存 baggage、HTTP 查询、合同原文或异常消息；本地可显式启用控制台导出。当前没有 OTLP 收集器和生产告警，不能将追踪测试视为可运维验收。
