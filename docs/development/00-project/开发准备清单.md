## 2. 范围裁决

1. MVP 后半段连接真实合同和财务系统的只读接口；前半段用模拟数据验证流程，详细接口字段可在后半段设计。
2. MVP 不向真实外部流程回写；只实现默认关闭的 outbox、Mock Delivery Adapter 和幂等验证。
3. MVP 不自动批准、签署、盖章或代替有权人员作最终决定。
4. 每个 AuditRun 以一个主合同及固定附件为待审对象，可另行绑定经选择和授权的历史合同、项目客户合同版本作为背景或义务比对材料。
5. 首版不跨案件复用结果；新版本或事实变化创建新运行。

## 3. 开工条件

以下事项完成后，M0 可开始：

- [x] 场景、交易角色、法域、规则数量和验收指标冻结；
- [x] 核心业务状态和失败语义冻结；
- [ ] Python 全栈候选、模块边界和持久任务方案通过 M0 Spike 并接受 ADR-004；
- [x] 首版 OpenAPI 和数据约束形成；
- [x] 第一条纵向规则达到“可开发”；
- [ ] 初始化 Git 仓库和分支保护；
- [ ] 创建 Python API/Worker 工程与 `uv.lock`；前端基于已定的 React + Ant Design 初始化，配套工具待 M0 确认；
- [ ] 完成 React + Ant Design 来源预览/证据回跳原型及前端配套工具决策记录；
- [ ] 完成 PageIndex 本地模式、OCR/解析和 AgentScope 稳定版技术验证；
- [ ] 建立本地 Compose、CI 和密钥样例；
- [ ] 准备首批合成合同与 JSON fixture；
- [ ] 登记本地 mock 与目标模型 profile。

未勾选项属于 M0 backlog，不阻止开始执行 M0；完成 M0 前不得进入 M1。

## 4. M0 退出条件

- 单份合成合同完成上传、解析、定位、运行、证据、人工任务和报告的纵向闭环；
- Worker 被终止后任务可恢复，重复领取不产生重复结果；
- OpenAPI 客户端和服务端桩可生成；
- 数据库迁移可从空库前进并回滚到上一个版本；
- `legal.payment_conditions` 的正例、反例、缺材料和冲突样例通过；
- 默认测试不访问真实商业模型和真实外部系统；
- 所有失败路径不被表达为专业通过。
