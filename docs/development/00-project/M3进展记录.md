## 已完成的工程切片

`contract_app.rules.obligations` 建立了闭合的 14 类稳定标识及与方案对应的中文名称。结构化候选契约仅允许 `candidate`、`needs_material`、`undetermined`、`human_review`，不存在自动通过/无风险状态；覆盖候选限制为 `covered`、`partial`、`missing`、`inconsistent`、`not_applicable`。适用性和覆盖状态必须一致；声称“未覆盖”必须带有下游缺失范围证据候选，不能仅凭没有摘录作结论。模型遗漏类别时，`complete_obligation_categories` 补成 `undetermined`，不填充结论或证据，因为遗漏输出本身不足以证明缺少材料。候选 Pydantic 对象及其数组使用冻结模型/tuple，避免校验后被内部调用方原地改写。

`bind_obligation_evidence` 可在调用方已完成授权与冻结快照读取后，将双侧引用绑定到指定合同版本和解析哈希；重新核验页码、唯一原文并计算 Unicode code point 偏移和引文哈希。对“未覆盖”候选，另要求下游解析无告警、服务端检索范围覆盖全部逻辑页，且模型提交的范围与服务端 `ObligationSearchTrace` 一致，才会生成 `parser_coverage=complete` 的绑定证据。检索轨迹现在同时绑定义务类别和文档版本，同一文档上不同类别须各自有对应轨迹；其构造会复制页面、章节和查询词容器为 tuple，并拒绝布尔/非法页码，防止输入 alias 改写范围或利用 `True == 1` 混淆完整页码检查。这只验证检索范围，不证明语义上不存在条款。

`bind_obligation_candidate_output` 将模型输出补齐为有序的 14 类，并将每类模型状态、适用性/覆盖候选、限制说明及已重新校验的双侧证据封装为不可变结果；模型整体限制原样保留。任何类别的引用越界、引文不唯一、搜索证明失配等校验错误都会使整个聚合调用失败，不返回部分绑定结果。模型遗漏的类别保持 `undetermined`、无证据，并明确说明不能视为已比对或未覆盖。该 helper 仍是纯校验/绑定边界：不负责授权、读取快照、执行检索、认定法律适用性或写入结果。

绑定证据现在同时保留原件 SHA-256、解析器版本、解析 JSON SHA-256、索引实际使用的源文件 SHA-256 及 renderer identity；DOCX 页码因而可以追溯到具体规范 PDF 和渲染环境。新增的 `documents.artifacts.serialize_parsed_document` 被解析 Worker 与 M3 来源校验共同使用，确保哈希算法与持久化字节完全相同。`ObligationEvidenceSource` 必须由可信调用方提供当前冻结输入的 `parsed_sha256`，并在对象构造时重算校验解析产物身份；PDF 必须绑定原 PDF 且不声明 renderer，DOCX 必须有规范 PDF 哈希和 renderer identity。`ParsedDocument` 与 `TextBlock` 的页面、块、告警和 bbox 序列在构造时复制成 tuple，并校验身份字段类型和有限坐标，防止调用方在哈希校验后通过原始 list 改写解析坐标或正文。该检查不替代来源读取时的成员授权及冻结快照核验。

材料链路新增 `customer_contract` 同案上传角色与 `upstream_comparison` 独立用途授权。上游材料只能上传在当前案件，要求本案主体已确认且合同绑定同一法人；审核人必须在选择时显式确认其属于本案同一法人项目。系统记录 `selected_by`、确认时间及 `case:<case_id>` 案件范围引用，但没有项目台账/合同系统做独立验证，不得称为系统核验。主合同可分别授权 `contract_review` 与 `upstream_comparison`；附件仅限 `contract_review`，客户合同仅限 `upstream_comparison`。目录按当前审核人逐用途返回文本/金额范围与有效/过期状态；撤权同时撤销该文档所有用途授权，过期授权可按新期限重授。授权投影与输入快照服务端按用途隔离，UI 已暴露同案客户合同上传、人工关联确认和逐用途权限状态，但尚未提供完整 14 类比对运行/结果流程。

来源工作流可显式选择 `contract_review` 或 `upstream_comparison` 用途并分别预览/冻结。上下游用途在前后端都要求本案待审主合同和至少一份同案、经审核人确认关系且授权/解析/索引就绪的项目客户合同；仅有主合同或任一侧未就绪时不得冻结。冻结仍只生成用途绑定的不可变输入快照；用户随后需从冻结卡片单独启动上下游比对运行，不接入跨案件搜索或真实外部来源。

## 上下游比对运行闭环（2026-10-19）

- 冻结后的 `upstream_comparison` 快照可通过独立运行入口创建 `upstream_comparison` 任务；共享 run 创建事务校验当前成员、快照用途/金额范围、案件版本、恰好一份主合同、至少一份已人工确认的上游合同及逐份当前授权。请求使用幂等键；每份上游合同最多 8 份，超出时拒绝运行，避免无界模型任务。
- Worker 只读取冻结输入中的主合同与上游合同，重新核对解析文件哈希、解析身份、索引身份和当前授权；模型读取前对冻结快照的每个逻辑页逐页调用授权索引。每份上游合同独立与唯一主合同比对，正文超过 80,000 UTF-8 字节或任一合同解析有实质告警时，不截断后猜测，而是输出 14 类 `needs_material`。
- 每组结果恰含 14 类候选，引用必须逐字回绑到上游/采购合同的冻结版本、页码及原文哈希。模型输出不合法、引用失配或搜索范围证明无效时，该组降级为 14 类 `undetermined`。候选“未覆盖”附带服务端对下游合同逐页关键词检索的类别级搜索范围；若本类关键词在任一页命中，会撤销“未覆盖”候选并降级为 `undetermined`。即便无关键词命中，搜索范围也不构成语义上不存在条款的证明。为适配当前 128K token 执行配置，单组双合同正文输入上限为 80,000 UTF-8 字节；超限时完整降级为 `needs_material`，不截断合同正文。
- API 独立返回上下游比对结果，并在读取时校验结果哈希、模型执行轨迹、14 类顺序、双边证据文件/解析器身份和来源哈希，同时要求当前成员对冻结输入中的全部文件仍有有效文本及金额授权。撤权后停止返回结果。前端可从冻结卡片启动任务，在运行历史中回到比对状态/结果页；结果页按上游合同和 14 类展示双边引文、复核限制、执行轨迹摘要并导出 Markdown 候选报告。
- 比对与现有合同审查共用 `APP_ENV=development|test` 及 `CONTRACT_REVIEW_EXECUTION_ENABLED=true` 开关和同一个 `contract-review-worker` 服务配置。运行依然依赖已配置的模型密钥、模型与 PageIndex；未启动 Worker 时任务会排队。没有将默认部署自动切换为真实合同模型执行。
- 此闭环不改变 M2/G2 门槛，不形成正式法律意见、合规认定、自动通过或签约结论。模型比较策略、14 类边界样例、双边金标和质量阈值仍需业务/法务/QA 验收；“候选未覆盖”必须由审核人复核。2026-10-19 本次仅记录前端生产构建与 OpenAPI 类型生成检查；未运行测试套件、真实合同处理或 M3 阶段门验收。

## 尚未完成 / 安全边界

- 14 类模型比对现已接入开发 Worker、任务结果存储、结果权限投影和 UI/Markdown 导出，但尚无经业务/法务/QA 验收的比对质量门槛。候选输出不代表已完成 M3 阶段验收。
- 当前只支持审核人将客户合同上传到当前案件并作人工同项目关系确认；无历史合同候选、跨案件材料选择、项目目录或合同系统独立核验。`case:<case_id>` 是案件范围引用，不是外部项目/合同 ID。
- 通用运行创建仅开放单合同审查快照的内部测试路径；上下游冻结快照即使本地测试 flag 开启，也不能通过 `start_bound_run` 生成 `contract_review` 任务。M3 比对 Worker/运行入口仍未实现。
- 绑定 helper 本身仍不做授权检查；Worker 先从当前有权且冻结的同一法人项目合同对创建来源对象，并对每一逻辑页走授权索引，再构造类别级缺失搜索轨迹。检索关键词命中范围不证明语义匹配/不匹配，审核人仍需核验原文上下文。
- “解析完整且检索遍历全部逻辑页”只证明声明的搜索范围，不证明语义上不存在匹配条款；`missing` 仍只是模型候选，须人工/评测核验，不能转成最终合同风险结论。
- 缺少上游合同、下游解析不完整、冲突、授权失效等路径不得映射成“未覆盖”；本切片没有实现这些来源/生命周期状态。
- 14 类字段和五种覆盖标签来自方案确认范围，但具体法律/业务匹配策略、边界样例、双边金标及阈值仍待相应负责人确定；候选不能被呈现为审核结论。
- M2 的法务/业务/企业知识/QA 审批、数组语义、规则执行及发布治理门槛仍未通过。M3 准备切片不等于绕过或通过 G2；真实材料与现场测试按用户授权留待后续。
