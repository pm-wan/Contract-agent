# 部署方案

> 版本：v1.0｜状态：已批准（内部 MVP）

## 1. MVP 部署形态

部署在内部受控环境，单租户使用，不向公众开放。应用数据和对象存储留在内部环境；模型必须经过 Model Gateway，供应商不得将输入用于训练，留存策略须可配置。生产化部署形态在 MVP 后重新评审。

## 2. 组件

- API Deployment；
- Worker Deployment（按审计和报告可设队列）；
- Python document-processing/PageIndex Adapter（可先与 Worker 同进程，资源隔离需要时部署为单独 Worker 进程）；
- PostgreSQL 高可用实例；
- MinIO 或等价 S3 兼容对象存储；
- Model Gateway；
- OpenTelemetry Collector；
- Secret/KMS。

## 3. 环境

MVP 使用 dev、test、mvp 三套逻辑环境；mvp 环境只使用内部授权或脱敏数据。规则和模型配置通过发布流程晋级，不手工复制。

## 4. 网络

数据库和对象存储不直接暴露公网；连接器使用明确出口和目标白名单；回调入口独立鉴权、限流和审计。

## 5. 容量

按页数、文件大小、并发案件、单案检查数、模型 token 和 OCR 建立容量模型。MVP 目标见 Phase 0 定义包。
