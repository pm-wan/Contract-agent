# 内部 MVP 技术栈基线

> 版本：v2.0 候选｜状态：按 2026-09-24 方案重定基线，待评审
> 适用范围：MVP 工程创建、开发、测试和部署
> 架构决策：[ADR-004：Python 全栈模块化单体](ADR/ADR-004-Python全栈模块化单体.md)
> 原则：先固定架构边界和兼容范围，具体依赖 patch 版本在工程初始化时以 lockfile 和镜像 digest 锁定；禁止未经验证的 alpha/beta 进入主链路。

## 1. 技术栈总表

| 层级 | 选型方向 | 用途与约束 |
|---|---|---|
| 后端语言 | Python 3.13.x | API、Worker、领域应用层、连接器、模型适配和文档流水线；单仓模块化单体，可分进程部署 |
| HTTP/API | FastAPI + Pydantic v2 | REST、SSE、输入输出 DTO、OpenAPI 3.1；依赖注入只放在边界层 |
| AI Agent 执行 | AgentScope Python 2.x 稳定版 | 受限工具调用、局部 Agent/Workflow 执行；框架不是业务流程、权限或任务状态真源 |
| 文档解析 | PyMuPDF、python-docx；OCR 组件经样本验证后选定 | PDF/DOCX 文本、页面、表格、坐标、解析警告；扫描件走可替换 OCR Adapter |
| 检索 | PageIndex Python SDK/Adapter（先验证本地模式） | 文档树索引与基于树的检索；不得承担案件权限和业务状态 |
| Skill 规范 | Markdown（`SKILL.md` + 引用文件） | 面向模型的执行指导保持 MD；当前仓库用于开发与评测。未来可用数据库管理目录、审核/发布状态和版本索引，但发布给运行时的内容仍是不可变 Markdown 快照 |
| 数据库 | PostgreSQL 18.x | 业务状态、任务、审计、规则/Skill 发布索引及 outbox；数据库是应用业务真源 |
| 数据访问/迁移 | SQLAlchemy 2.x Core/显式 SQL + Alembic，或在 M0 决策是否采用 SQLModel | 关键事务、RLS、租约和 outbox 使用显式 SQL；不把 ORM 对象泄漏进领域层 |
| 工作队列 | PostgreSQL 持久任务表 + `FOR UPDATE SKIP LOCKED` | MVP 避免第二个任务真源；应用负责 lease、fencing、重试、取消、幂等和恢复 |
| 对象存储 | S3 API（MVP 可用 MinIO） | 原件、解析产物、PageIndex 索引/快照、结果与报告；访问经授权签名/适配器 |
| 前端框架 | React | 已确定；具体主版本在工程初始化时核验并锁定 |
| UI 组件 | Ant Design | 已确定；具体主版本及组件/主题约束在工程初始化时锁定 |
| 前端配套栈 | 部分待定 | 是否采用 TypeScript、构建/包管理工具、路由/状态/表单方案、测试工具等未形成约定；M0 按团队能力、审阅交互、部署和维护成本确定 |
| API 契约 | OpenAPI 3.1 | Python API 与前端客户端生成/兼容性检查的契约真源 |
| Schema | JSON Schema 2020-12 | 规则、槽位、模型结构化输出和导入数据校验 |
| 可观测性 | OpenTelemetry | API、任务、Agent、PageIndex、模型调用 trace 关联 |
| 部署 | Docker Compose（MVP）；后续按客户环境评估 | API、Worker、PostgreSQL、对象存储、Web、观测组件；不是微服务前提 |
| Python 工具链 | uv + Ruff + mypy（或 pyright，M0 固定其一）+ pytest | 环境、锁文件、格式/lint、类型和测试 |
| 前端工具链 | 随前端 ADR 决定 | 不预设 Node.js、pnpm、TypeScript 或具体 lint/test 工具 |

具体 patch 版本按 M0 的官方稳定版核验记录锁定到对应 lockfile、容器 digest 与 SBOM；前端框架/UI 已定，但配套栈待决，因此不预设 `pnpm-lock.yaml`。

## 2. Python 应用结构

采用“一个代码仓库、一个模块化单体、API/Worker 可分进程部署”。首期不拆微服务；进程按负载、故障隔离或部署权限拆分，但共享同一套领域与应用代码。

```text
apps/
  api/                 # FastAPI 路由、认证、SSE、OpenAPI
  worker/              # PostgreSQL job poller 与任务执行入口
packages/contract_app/
  domain/              # 纯业务对象、规则解释结果和不变量
  application/         # 用例、事务边界、授权裁剪、计划调度
  ports/               # Repository、模型、解析、检索、来源、存储接口
  adapters/            # PostgreSQL、S3、PageIndex、AgentScope、模型和来源适配
  workflows/           # 固定、可审计的业务工作流
  skills/              # 加载已发布的 Markdown Skills；不得动态执行任意代码
  schemas/             # DTO、规则、事实和输出契约
```

依赖方向：`api/worker → application → domain`，`adapters → ports`。领域层不得依赖 FastAPI、AgentScope、PageIndex、ORM、供应商 SDK 或 Web 层。AgentScope 中间件、消息、Session 和模型对象须在 adapter 内转为应用自有 DTO。

## 3. AgentScope 使用边界

- AgentScope 只运行被应用计划调度的有限步骤，例如条款候选抽取、已授权材料的证据补充、结构化风险解释。
- “必须审哪些项”、适用性、权限、金额、上下游合同关联、结果分级、人工审批和最终报告覆盖率由应用代码与已发布规则控制。
- 对模型输出做 Pydantic/JSON Schema 验证、引用回查、权限二次检查和业务规则校验；校验失败进入重试或人工队列，不得默认为通过。
- 工具采用显式 allowlist，按运行用途给最小数据投影；不向模型传输未授权原文、其他合同全文或无关字段。
- AgentScope 会话/检查点可以辅助局部恢复；案件、任务、输入快照、知识版本、结果和人工决定的唯一真源仍是 PostgreSQL 与不可变对象存储快照。
- Agent/Tool 执行设置步数、时长、token、费用和重试上限；任何 Agent 不能自行扩权、改变审查计划或绕过人工节点。

## 4. PageIndex 与文档处理边界

PageIndex 作为检索实现，不是权威法律来源，也不自动赋予跨文档读取权限。M0 先以脱敏/合成 PDF 验证本地 Python SDK：树索引质量、页码/片段引用、增量更新、删除、索引重建、并发、资源用量和本地持久化。MVP 暂不依赖 Cloud/MCP，不上传真实合同到未获批准的外部托管服务。

本地 PageIndex 面向 PDF 文本层；扫描件、复杂图像和 OCR 先通过文档预处理 Adapter 生成可审计文本/坐标，再决定是否索引。PageIndex 版本、索引配置、文档哈希、树快照和检索引用必须随 AuditRun 留档。检索返回的引用必须能回到被冻结的合同/来源快照和页码；检索没有命中不能作为“无风险”证据。

合同解析流程：

```text
原件只读 → 类型/安全检查 → PDF/DOCX 解析 → OCR（需要时）
        → 规范化 ParsedDocument（页/块/字符范围/bbox/表格/告警/哈希）
        → PageIndex 索引 Adapter → 带来源引用的检索结果
```

解析产物与原件分开存储。坐标和 offset 使用统一 Unicode 字符单位，并记录 parser 版本、规范化版本和内容哈希。质量不足、加密文件、缺页、乱码或引用无法回跳时生成显式告警并降级/人工复核。

## 5. API、数据和持久工作流

- FastAPI 负责边界协议；OpenAPI 3.1 为前端与集成方契约。API 接受命令后返回任务/运行 ID，通过查询和 SSE 获取进度，不长时间占用 HTTP 请求。
- PostgreSQL 持有案件、授权、输入冻结快照引用、任务租约、运行、结果、人工任务、发布版本和审计事件。
- 任务以 at-least-once 执行，应用服务保证幂等提交；lease/fencing token 阻止过期 Worker 写入；业务结果与 outbox 在同一事务提交。
- 模型、OCR、PageIndex、对象存储和外部接口调用均在数据库事务外执行；调用前记录可恢复的步骤意图，完成后以运行 ID、节点 ID、输入哈希幂等落库。
- 金额存 `numeric`，Python 用 `Decimal`，禁止二进制 float 表达业务金额。
- 权限在应用 service 层以案件、字段、用途进行检查和投影；数据库 RLS 作为防御纵深而非唯一授权机制。
- 每次运行记录 parser/OCR/PageIndex/索引配置/AgentScope/Skill/规则/提示词/模型/API Schema 版本以及各输入哈希。

## 6. 安全、隐私与隔离

- 非开发环境接入 OIDC；每个 API/Worker 使用独立服务身份。开发 seeded user 不能进入验收环境。
- 上传执行大小、MIME、magic bytes、压缩炸弹、恶意内容和宏检查；原件只读。
- 租户与合同授权在查询、预览、冻结、模型输入、PageIndex 检索、结果投影、报告、导出和日志各环节重新校验。
- 任务只持有授权后输入快照引用；Worker 读取时验证快照归属、用途和授权版本。授权撤销后的派生数据遵循已批准的删除/保留策略。
- 日志禁止输出合同全文、密钥、模型隐藏推理；敏感字段脱敏，trace 只记录稳定 ID、哈希和诊断元数据。
- PageIndex Cloud、外部 OCR/模型服务必须单独过数据出境/保留/训练/区域与授权评审后，才可启用；MVP 默认关闭。

## 7. 开发、测试与交付

### Python

- uv lock；Ruff format/lint；mypy 或 pyright 固定一种；pytest；pip-audit/依赖 SBOM。
- pytest 单元测试、PostgreSQL 集成测试、API 契约测试、架构依赖测试、PageIndex/OCR adapter 合成样本测试。
- 架构测试保证 domain 不依赖 FastAPI、ORM、AgentScope、PageIndex 或 provider SDK；依赖规则和授权过滤有负向测试。

### React + Ant Design 前端

- React 与 Ant Design 已确定，不再作为 M0 待选项；M0 只需补齐配套语言、构建/包管理、路由/状态/表单和测试工具的决策。
- 前端应覆盖长文档与证据审阅、表格/筛选、可访问性、加载/错误/空状态、OpenAPI 客户端生成和自动化测试。
- API 继续以 OpenAPI 3.1 为契约；客户端生成方式随前端配套栈决策确定。

### 必须的纵向测试

- API/Worker 重启、任务重复投递、lease 超时与 fencing、取消、重审和幂等提交；
- AgentScope 中断/恢复、非法结构化输出、工具越权拒绝、成本/时限上限；
- PageIndex 索引复用、重建、文档版本变更、授权过滤和引用回跳；
- OCR 误识、解析失败/低置信度、坐标偏移、错误引用不得输出为确定结论；
- 主合同、授权关联合同、未关联合同、跨租户和撤权等权限场景；
- 使用固定金标评测覆盖率、证据准确性、误报/漏报、成本和端到端延迟。

## 8. 不采用与触发重评

| 暂不采用 | 原因/触发条件 |
|---|---|
| Go/Eino 作为 MVP 主栈 | Python 文档解析、PageIndex SDK 和 AgentScope 构成一条相邻生态链；不为尚未出现的吞吐/运维需求承担双后端运行时。若出现团队标准、容量或部署限制，另立 ADR 用基准测试复评 |
| Python 多微服务 | 首期领域和团队规模不足；只按 API/Worker 进程角色部署 |
| 独立工作流引擎、Kafka、Redis 队列 | PostgreSQL 任务表足以验证规模和持久语义；容量或调度复杂度触发后再评估 |
| PageIndex Cloud/MCP | 合同数据托管、OCR、数据区域、保留和客户授权尚未完成评审；本地/自建 Adapter 优先 |
| Agent 自主决定计划、法律结论或权限 | 无法保证必审覆盖、可复现、可审计和最小授权 |
| 直接将 PageIndex 树或 ORM/AgentScope 类型作为领域模型 | 绑定供应商/框架并破坏可迁移性；通过应用 DTO 与 port 隔离 |

## 9. M0 技术 Spike 与架构门

M0 结束前完成以下证据，未完成不得声称方案已生产就绪：

1. **文档与 PageIndex**：至少覆盖原生 PDF、长合同、表格、扫描页和混合 PDF；比较文本抽取/OCR 与 PageIndex 引用回跳、树重建和检索质量；明确扫描件预处理路线。
2. **AgentScope**：验证稳定版 Python API、结构化输出、工具 allowlist、超时/取消、局部状态恢复和依赖版本；AgentScope 故障不丢失应用任务。
3. **PostgreSQL 持久工作流**：kill/restart、重复领取、fencing、幂等、人工等待和取消测试通过。
4. **权限链**：验证查询前授权、预览冻结、模型投影、检索过滤、派生结果和导出各环节，确认不同合同材料不能因共用索引而互相泄露。
5. **前端配套栈**：React + Ant Design 已确定；确认其余配套工具，并走通来源选择/预览冻结和证据回跳交互原型，记录理由与版本。
6. **单仓工程**：Python API、Worker、所选前端、PostgreSQL、MinIO、对象存储和观测最小环境可复现启动，CI 锁依赖并跑架构/契约测试。
7. **ADR 复核**：记录性能、资源、费用、私有化、许可证和安全扫描结果；若核心门槛失败，给出可验证的替代方案，而非直接恢复双语言架构。

## 10. 版本和升级策略

- M0 记录依赖来源、许可证、版本、镜像 digest 和 CVE；禁止 floating tag/`latest`。
- 安全 patch 经 CI 与关键金标通过后升级；主版本升级需 ADR 或升级记录。
- Python、AgentScope、PageIndex、解析器/OCR、前端技术栈、模型、规则/Skill 任一变化，按影响范围重跑金标与回归。
- AgentScope 和 PageIndex API 先封装于 adapter，升级时使用兼容测试；框架 checkpoint 不作为长期业务数据格式。
