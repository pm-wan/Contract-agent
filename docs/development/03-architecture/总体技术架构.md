# 总体技术架构

> 版本：v1.1 候选｜状态：按 9 月 24 日范围修订中
> 架构形态：Python 全栈模块化单体；API 与 Worker 可独立部署

## 1. 逻辑架构

```text
Web / OpenAPI / upload / optional source adapters
             │
       FastAPI + IAM + SSE
             │
  application services / fixed plan compiler
             │
 domain + ports + PostgreSQL durable workflow
       ┌─────┼───────────┐
 adapters  AgentScope   reporting / context
       │       │                 │
 PageIndex / models        PDF/DOCX/OCR
 finance/contract
 external source (later)
```

## 2. 部署单元

- `contract-audit-api`：Python/FastAPI 同步命令、查询、鉴权和 SSE；
- `contract-audit-worker`：同一 Python 应用代码中的任务领取、检查、模型、连接器和报告执行器；
- `document-processing`：Python 解析/OCR/PageIndex adapter，可在资源隔离需要时作为独立 Worker 进程部署，不拥有案件业务状态；
- PostgreSQL；
- MinIO（MVP）或其他 S3 兼容对象存储；
- 观测和密钥设施。

API 与 Worker 共享领域代码和 PostgreSQL，但使用不同服务身份、数据库角色与资源限制。Web 客户端采用 React + Ant Design；语言与构建等配套工具在 M0 补齐决策。MVP 后端采用 Python，不建设 Go 后端。

## 3. 关键设计

- Ports and Adapters 隔离外部系统与领域；
- PostgreSQL 持久任务表承载首期工作流；
- at-least-once 执行，结果提交幂等；
- outbox 保证外部事件最终发送；
- 输入、计划和结果不可变；
- 模型调用经过统一网关；
- AgentScope 只执行应用已批准计划中的受限步骤；PageIndex 只提供版本化、可回跳的检索能力；
- 所有外部内容视为不可信数据。
- 已启用且获授权的数据源在运行前查询、预览并冻结；服务端按任务用途裁剪模型输入和派生结果。
- 分类、通用/专项审查、14 类上下游比对和三类结果在应用持有的计划与状态内运行。

真实财务与合同只读接口属于本轮 MVP，详细适配、联调安排在实施后半段；前半段模拟数据只用于验证流程。外部经营/信用数据安排在末段。运行时 Skill 自行查源系统不在本轮。

## 4. 暂不引入

Go/Eino 双后端、六域微服务、通用 ETL、图数据库、独立工作流引擎和任意代码沙箱。只有出现明确容量、组织或运维证据后再评估；如果需拆 OCR/索引进程，仍使用 Python 与自有契约，不因此拆分业务真源。

## 5. 非功能目标

旧 100 页、5 并发、P95 15 分钟和 30 元/单案只针对 2026-09-17 内部验证范围。本轮按待审/上游合同页数、历史候选数、财务明细数和启用来源组合重新测量目标；架构仍须支持任务恢复、成本限制、审计回放和组件版本追踪。
