# 持久工作流设计

> 版本：v1.0｜状态：已批准（内部 MVP）  
> 负责人：内部技术负责人  
> 批准人：内部项目发起人  
> 适用阶段：M0～M4  
> 上游依据：ADR-002、业务流程与状态机 v1.0

## 1. 目标

支持长时间人工等待、Worker 崩溃恢复、重复投递、外部接口失败、取消、版本替换和定向重审。

## 2. 任务模型

最小字段：task_id、tenant_id、run_id、task_type、payload_ref、status、priority、attempt、next_run_at、lease_owner、lease_until、fencing_token、idempotency_key、last_error、version。

## 3. 执行语义

- 至少一次领取；
- 任务处理幂等；
- lease 过期可重领；
- fencing token 阻止旧 Worker 提交；
- 取消和 superseded 在提交前再次校验；
- 重试次数、退避和总预算由应用拥有。

## 4. 人工等待

等待材料、数据或人工时，将检查置为持久等待状态并创建 HumanTask，不占用 Worker 或模型调用。

## 5. AgentScope / PageIndex 边界

AgentScope session/checkpoint 以及 PageIndex 索引/树快照均是可替换的局部执行或检索状态，不是业务真相。数据库保存任务、计划、输入快照引用、结果、人工状态和决定；不可变对象存储保存原件与必要的检索/解析快照。框架 checkpoint 丢失时，任务必须能从固定输入与版本重新执行，或进入可解释的人工处置，不能导致案件不可恢复。

AgentScope 只执行应用已编译计划中的有限节点。PageIndex 查询只能作用于服务端构造的授权文档集合；禁止依赖“共用一个索引但由 prompt 保证不越权”。结果引用落库前再校验合同 ID、文档哈希、页码/块定位和当前授权。

## 6. 重审

输入变化触发 dependency matcher，生成受影响 check_instance 集合。首期可先创建完整新运行并复用已验证结果引用；不得原地修改旧结果。

M0 裁决：先创建完整新运行，不复制旧 CheckResult；旧结果仅用于 UI 差异展示。定向执行优化在 M3 实现，但必须保持新运行拥有完整覆盖视图。

## 7. 领取与提交协议

1. Worker 使用 `FOR UPDATE SKIP LOCKED` 领取 `queued` 且 `next_run_at <= now()` 的任务；
2. 领取时递增 fencing_token，写入 lease_owner/lease_until，并把状态置为 running；
3. 网络和模型调用在事务外执行；长任务在有效 token 下有限续租；
4. 提交事务按 task_id + fencing_token 更新，旧 token 更新行数为 0；
5. 结果、任务终态和 outbox 事件在同一事务提交；
6. retryable 错误计算退避并回 queued，超过次数/时间/成本预算后进入 failed；
7. 幂等键在租户和任务类型范围内唯一。

## 8. 默认参数

| 参数 | M0 默认值 |
|---|---:|
| lease | 60 秒 |
| heartbeat | 20 秒 |
| 普通任务最大尝试 | 5 |
| 模型调用最大尝试 | 2 |
| 退避 | 指数退避 + jitter，上限 10 分钟 |

具体值可配置，但修改必须记录运行配置版本。
