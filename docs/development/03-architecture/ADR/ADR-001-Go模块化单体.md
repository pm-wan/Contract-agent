# ADR-001：首期采用 Go 模块化单体（已被取代）

> 状态：已取代｜原决定日期：2026-09-17｜取代日期：2026-09-25
> 当前技术基线见 [ADR-004：Python 全栈模块化单体](ADR-004-Python全栈模块化单体.md)。本文保留为决策历史，不再作为实施依据。

## 背景

首期领域仍在收敛，团队需要快速完成纵向闭环，同时保持 API 与 Worker 独立扩容。

## 决定

采用 Go 模块化单体，按领域包隔离；API 与 Worker 可分进程部署，共享代码与 PostgreSQL。

## 后果

降低分布式事务和运维复杂度，但要求严格模块边界。只有容量、组织所有权或故障隔离出现明确证据时拆分服务。

## 验证

以包依赖检查、架构测试和性能测试验证边界与容量。

## 回滚条件

若纵向 Spike 证明 Python sidecar 或独立扩缩容边界无法通过模块内 adapter 维护，可新增受控部署单元；若容量、故障隔离或组织所有权出现证据，再以新 ADR 评估服务拆分。
