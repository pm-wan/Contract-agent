# ADR-005：React + Ant Design 前端配套栈

> 状态：M0 工程基线；浏览器/可用性验收仍待目标用户评审｜日期：2026-09-25
> 上游：[实施计划与里程碑](../../00-project/实施计划与里程碑.md)、[页面与交互说明](../../01-product/页面与交互说明.md)

## 背景

React + Ant Design 已由用户确定，但类型语言、构建、路由、测试和前后端契约生成仍未锁定。M0 需要能快速验证来源状态和证据回跳，同时不把本地原型误认成具备授权与冻结能力的产品。

## 决定

用户已确认 React + Ant Design。M0 配套采用 TypeScript、Vite、React Router、pnpm 锁文件、Vitest + Testing Library、ESLint。前端独立置于 `web/`，由 FastAPI 提供业务 API/OpenAPI；M1 再由真实 OpenAPI 生成类型化客户端，禁止用前端数据遮挡作为权限控制。路由为案件列表、案件工作台、运行结果、人工任务，来源和证据面板先落在工作台内。

## 选择理由与边界

TypeScript 帮助守住来源状态、结果与版本的接口形状；Vite/React Router 足够支撑内网单页工作台；Ant Design 覆盖中文表格、表单、抽屉和状态组件。当前原型的本地数组只是交互夹具，没有网络查询、用户身份或任何授权语义。真实来源与冻结协议由后端负责，前端只能显示后端返回的可见投影。长期状态管理暂不引入额外库；待 M1 API 的缓存、撤权和失效契约稳定后评估。文档原文定位先用合成文本验证页码边栏与抽屉交互，正式 PDF/OCR 组件须基于样本测定位精度。

## 备选方案与后果

可选 Next.js 或更重的状态管理/请求缓存框架，但目前没有 SSR、公众页面或复杂客户端缓存的证据，先不引入。Vite 单页应用部署简单，代价是业务 SEO/SSR 能力不在当前基线；React Router 的路由级拆包、真实 API 请求失效和静态资源发布策略需在 M1 完成。前端依赖升级按锁文件和自动化检查控制，不从版本号推断兼容性。

## 验证与未决项

工程检查为 `pnpm --dir web lint`、`pnpm --dir web typecheck`、`pnpm --dir web test`、`pnpm --dir web build`。M0 原型验证只覆盖可见状态、选择意图和引用回跳；不得充当真实权限/冻结验收。目标浏览器、辅助技术、团队既有能力、可用性评审、长表格、失败重试和真实 PDF 定位仍须获得人员与样本证据。M1 接入前要增加服务端分页、请求取消/过期响应防护、API 合约测试、撤权清缓存和端到端测试。

## 重评条件

若目标部署环境不支持当前浏览器/Node 构建产物、Ant Design 关键组件无法满足可访问性或文档定位需要另用框架，则记录实测证据并重评局部工具；不自动推翻 React + Ant Design 的用户决策。
