# 模型网关设计

> 版本：v1.0｜状态：已批准（内部 MVP 接口）  
> 负责人：内部技术负责人  
> 批准人：内部项目发起人  
> 适用阶段：M0～M4  
> 上游依据：总体技术架构、规则与槽位规范 v1.0

## 1. 职责

- 统一模型供应商和版本；
- 请求级租户、用途和数据策略；
- Prompt/Skill 版本绑定；
- 结构化输出校验；
- 超时、重试、限流、熔断和预算；
- 内容脱敏、审计和成本计量；
- 禁止供应商格式进入领域层。

## 2. 请求契约

请求至少包含：task_type、tenant_policy、model_profile、input_refs、output_schema、tool_allowlist、time/token/cost budget、trace_id。

## 3. 输出处理

模型输出先作为 Candidate。依次通过 JSON Schema、来源、证据、业务一致性和权限验证后才能写入 SlotState。

## 4. 工具控制

必须调用的确定性工具由应用直接调用。模型可选择的工具仅来自本轮白名单；参数经过 Schema、授权和用途校验；工具结果仍需映射为受控证据。

## 5. 数据策略

- 默认最小上下文；
- 敏感字段优先在本地工具比较；
- 记录请求元数据和输入引用，不记录隐藏思维链；
- 供应商留存、训练、地域和删除能力必须配置化并经安全批准。

## 6. 降级

模型不可用时，不得自动通过。按任务类型进入重试、替代模型、人工复核或受限报告；替代模型使用必须满足已批准 profile。

## 7. Port

```text
GenerateStructured(ctx, ModelRequest) -> ModelCandidate | ModelError
```

`ModelRequest` 必含 request_id、tenant_id、case_id、run_id、task_type、model_profile、prompt_version、skill_hash、input_refs、output_schema_ref、tool_allowlist、timeout、token_limit、cost_limit_cny 和 trace_id。`ModelCandidate` 必含 provider、model_version、output、usage、cost、latency、finish_reason 和 response_hash。

错误分类固定为：`invalid_request`、`forbidden`、`timeout`、`rate_limited`、`provider_unavailable`、`invalid_output`、`budget_exceeded`、`cancelled`。只有显式标记 retryable 的错误可重试。

## 8. M0 模型策略

- 默认使用确定性 MockModel，按 fixture 返回合法、非法、超时和工具越权响应；
- 真实模型 profile 未登记供应商版本、数据地域、留存/训练策略和评测结果前不得处理合同原文；
- 模型输出只保存为 Candidate，经 Schema、证据和业务验证后才能写入槽位；
- 日志保存元数据、引用、哈希和用量，不保存隐藏思维链。
