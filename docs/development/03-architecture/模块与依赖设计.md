# 模块与依赖设计

> 版本：v1.1 候选｜状态：按新范围修订中
> 负责人：内部技术负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：ADR-001、领域模型 v1.0

## 1. Python 包结构建议

```text
apps/api
apps/worker
packages/contract_app/
  domain/ application/ ports/ adapters/
  cases/ documents/ facts/ knowledge/ policies/
  execution/ checks/ decisions/ integrations/
  reporting/ identity/ auditlog/
  contextassembly/ obligationmatching/ resultprojection/
  workflows/ schemas/ skills/
```

每个业务模块内部按 `domain / application / ports / adapters` 组织；不要建立一个共享 `utils` 承载业务逻辑。

## 2. 依赖规则

```text
api/worker → application → domain
adapters → ports
domain ✕ FastAPI/ORM/AgentScope/PageIndex/vendor SDK
```

跨模块通过应用服务、只读查询接口或领域事件协作，不直接修改他人聚合表。

## 3. 事务边界

- 单聚合写入尽量单事务；
- 结果、任务状态和 outbox 事件同事务；
- 模型、网络、对象存储和人工等待在事务外；
- 外部回调通过 outbox 异步发送。

## 4. 版本边界

Parser、mapping、rule、skill、prompt、model、executor 和 report template 均需独立版本，并写入 AuditRun。

## 5. 模块协作规则

- `cases` 不读取 checks 表形成业务决定；
- `execution` 只调度计划节点，不解释法律或企业规则；
- `checks` 通过 facts/knowledge 的只读 port 获取固定快照；
- `decisions` 只追加决定和人工任务，不修改 CheckResult；
- `integrations` 负责映射、快照与投递，不将外部 DTO 泄漏到 domain；
- `reporting` 读取不可变结果视图，不成为事实或决定真源。
- `contextassembly` 只读已授权来源，预览确认后冻结关系、查询结果与知识版本；模型任务只能取得服务端裁剪的视图。
- `obligationmatching` 基于双方固定文档版本和双边证据，输出适用性与覆盖候选，不自行建立未授权合同关联。
- `resultprojection` 将后台判断映射为合同发现、决策参考、范围提示，并按当前权限供页面、报告和导出使用。

新逻辑模块暂在模块化单体内实现；是否拆服务由新负载和运维证据决定。真实适配器的详细设计与联调在 MVP 后半段进行。

CI 使用 import-linter/架构测试禁止 domain 引入 FastAPI、ORM、AgentScope、PageIndex 或供应商 SDK。Python adapter 将框架数据结构转为自有 DTO；AgentScope 的 session/checkpoint 不进入业务 schema。
