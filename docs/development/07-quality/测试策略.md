# 测试策略

> 版本：v1.0｜状态：已批准（测试基线；执行结果待产出）  
> 负责人：内部测试负责人  
> 批准人：内部项目发起人  
> 适用阶段：M0～M4  
> 上游依据：用户故事与验收标准 v1.0、验收方案 v1.0

## 1. 测试层级

| 层级 | 重点 |
|---|---|
| 单元 | 规则适用性、金额日期、状态机和验证器 |
| 属性/模糊 | 金额、Unicode 定位、Schema、分页和幂等 |
| 契约 | 合同/财务/模型/对象存储接口 |
| 集成 | PostgreSQL、任务、outbox、RLS、对象存储 |
| 端到端 | 上传至报告、人工等待、重审和回写 |
| 评测 | 规则、槽位、证据、结论和稳定性 |
| 故障注入 | Worker kill、超时、重复、乱序、部分返回 |
| 安全 | 越权、提示注入、恶意文件、密钥和日志泄露 |

## 2. 必测业务场景

- 缺材料不得通过；
- 引文不匹配不得完成关键槽位；
- 同请求重复提交只产生一个业务结果；
- 旧 Worker 的过期租约提交被拒；
- 撤回/换版后旧结果不可回写；
- 人工纠正只失效依赖结果；
- 外部接口无权限与空结果不同；
- 模型不可用时进入明确降级状态。

## 3. 测试数据

自动测试默认使用合成或脱敏数据。生产数据调试必须经过审批，不得复制到个人环境。

## 4. 发布回归

代码、规则、Skill、Prompt、模型、解析器、映射器或规范版本变化均可能触发不同范围回归；影响矩阵由 CI 计算并保存报告。

## 5. M0 CI 门禁

- Python：Ruff format/lint、mypy 或 pyright、pytest、架构依赖检查；数据库并发任务测试覆盖 lease/fencing/idempotency；
- TypeScript：格式、lint、`tsc --noEmit`、组件测试；
- 契约：OpenAPI lint、生成代码无漂移、JSON/YAML Schema 校验；
- 数据库：空库迁移、向前兼容检查、RLS 跨租户反例；
- 规则：Schema、引用、四类种子用例和禁止判断断言；
- 安全：密钥扫描、依赖漏洞扫描、恶意文件与提示注入种子。
