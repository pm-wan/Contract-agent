# 权限模型

> 版本：v1.1 候选｜状态：按 9 月 24 日范围修订中
> 负责人：内部技术负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：领域模型 v1.0、责任矩阵  
> 原则：默认拒绝、最小权限、用途约束、全链路留痕

## 1. 权限维度

- tenant；
- organization/legal_entity/ledger；
- case；
- document/fact field；
- data source and record；
- purpose；
- operation；
- time validity。

## 2. 角色不等于全部权限

角色提供基础能力，具体访问还需满足案件成员、法人/账套、数据用途和字段策略。模型和工具不能因为拿到 case_id 就自动获得案件全部数据。

### 选入其他合同和金额的权限

“跨合同”在本轮仅指审核当前采购合同时，工作人员明确选入另一份客户合同做上下游分析，或选入一份历史合同作背景。选择动作不自动授予全文、金额或项目用途的读取权；每份合同须分别校验选择人、案件用途、我方法人、源系统记录、文档版本和字段权限。无权时返回 `forbidden`，相关分析按受限状态处理，不从候选摘要或模型记忆补足内容。

对审核人直接上传到当前案件的项目客户合同，当前没有项目台账或合同系统记录可供校验：服务端仅接受已确认同一我方法人的案件成员上传，并要求案件审核人在建立 `upstream` 关系时显式确认该合同属于本案同一法人项目。`relation_ref` 只记为当前案件范围（`case:<case_id>`），`relation_verified_at` 与 `selected_by` 记录人工确认时间和人员；这不是系统对项目关系的独立核验，不得向用户或模型描述为“已与项目台账核实”。历史合同候选、跨案件材料选择及合同系统来源记录在其来源身份、关系核验和独立授权流程就绪前保持关闭。

服务端在上下文组装及模型每次读取时生成任务范围的授权视图；金额只有在该检查确需且已获字段授权时才可进入模型输入。财务计算可在受控执行器内使用原值，再按接收者权限输出结果。模型回答、合同摘要、SSE、报告、导出、缓存和日志均按相同字段与用途策略裁剪；前端遮挡仅是附加呈现措施。每次读取和导出重新校验当前权限。

## 3. 高权限操作

| 操作 | 控制 |
|---|---|
| 查看完整银行账户 | 原则上禁止给模型；受控工具比较 |
| 纠正关键事实 | 具名权限 + 理由 + 版本 |
| 更正已确认的案件主体 | 确认后锁定，普通审核人不能直接更改；仅当前租户 `tenant_entity_administrators` 中的业务管理员可纠错，要求理由、期望案件版本并追加不可变审计。管理员不要求是案件成员；通过独立队列/纠错上下文只读取案件名称/ID、当前主体和版本，普通案件详情、材料、结果、运行历史仍严格要求成员身份，纠错不自动授予成员资格。授权/撤销由受信运维流程处理，应用 API 不提供自助提权；不得把 `operator` 运维角色或 OIDC 任意角色声明直接视为主体管理员。管理员可在选择、授权和冻结后纠错：撤销当前选择/材料授权，递增案件版本，将旧范围运行标记为 `superseded`，但保留冻结快照和运行历史。原主体下的 `DocumentVersion` 不可变并保留原范围；新审查须由案件成员在更正主体范围下上传新材料版本、重新选择/授权、预览和冻结。旧结果仍按当前成员与材料授权条件重新鉴权 |
| 批准企业例外 | 审批矩阵 + 有效期 |
| 发布规则 | 作者/批准人分离 |
| 外部回写 | 登记目标 + 签名 + 幂等 + 当前版本校验 |
| 导出完整报告 | 水印/日志/按角色脱敏 |

## 4. 租户隔离

应用层强制 tenant 条件；数据库启用 Row-Level Security；对象存储使用租户前缀和独立授权；检索索引带租户过滤；后台运维访问使用审批和审计。

### 身份声明与应用授权的边界

OIDC 仅负责验证身份提供方签名的 issuer、audience、时效、subject 和已配置的租户 UUID claim。应用 actor ID 由规范化 issuer 与不可变 `sub` 确定性派生，不使用 email、显示名或 IdP 角色作为业务身份/权限；同一 subject 在不同 issuer 下属于不同身份。租户/案件成员及其角色仍以 PostgreSQL 当前成员关系为准，IdP Token 中即使携带角色也不能绕过案件成员与用途/字段授权。身份验证成功不代表自动获得任何案件访问权。真实 IdP、租户 claim 和用户成员预置映射须由部署/身份负责人联调确认。

## 5. 权限变化

历史结果可保留不等于当前用户仍可查看。每次读取重新校验当前权限；导出物保留当时的授权和生成记录。

## 6. MVP 角色能力

| 能力 | submitter | reviewer | finance_reviewer | rule_admin | approver | operator |
|---|---:|---:|---:|---:|---:|---:|
| 创建案件/上传材料 | 是 | 是 | 否 | 否 | 否 | 否 |
| 查看授权案件基本状态 | 是 | 是 | 是 | 否 | 是 | 是 |
| 查看完整法律分析 | 否 | 是 | 按字段 | 否 | 是 | 按应急授权 |
| 确认法律事实 | 否 | 是 | 否 | 否 | 否 | 否 |
| 确认财务事实 | 否 | 否 | 是 | 否 | 否 | 否 |
| 编辑规则草案 | 否 | 否 | 否 | 是 | 否 | 否 |
| 作案件决定 | 否 | 否 | 否 | 否 | 是 | 否 |
| 运维任务恢复 | 否 | 否 | 否 | 否 | 否 | 是 |

`entity_admin` 是独立租户级业务授权，不扩大案件材料读取权限；管理员纠错接口只为已确认主体写入更正，不因该授权获得案件审查或材料查看权。OIDC subject 仍由应用映射为稳定 actor UUID，授权记录绑定该 actor。

所有能力还必须满足 tenant、case membership、purpose 和字段策略。MVP 虽为单租户，仍必须保留 tenant_id、应用过滤和 RLS 测试。
