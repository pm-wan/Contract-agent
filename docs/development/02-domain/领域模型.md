> 版本：v1.1 候选｜状态：按新范围修订中
> 负责人：技术负责人 + 领域负责人
> 批准人：内部项目发起人
> 适用阶段：M0～M4
> 上游依据：PRD v1.1、业务流程与状态机 v1.0

## 1. 限界上下文

| 上下文 | 职责 | 不负责 |
|---|---|---|
| cases | 案件、用途、外部绑定和生命周期 | 专业判断 |
| documents | 原件、版本、解析和定位 | 选择事实真值 |
| facts | 事实候选、确认、冲突和快照 | 法律结论 |
| knowledge | 规范原文、版本和引用关系 | 执行检查 |
| policies | 规则包、企业立场、适用性和发布 | 案件调度 |
| execution | 计划、任务、槽位、依赖和恢复 | 业务规则作者 |
| checks | 领域执行器和结构化结果 | 最终审批 |
| decisions | 人工任务、决定、例外和报告 | 改写历史结果 |
| integrations | 外部系统能力与数据映射 | 领域字段猜测 |

## 2. 聚合根

### AuditCase

约束：属于一个租户；明确用途和流程主系统；可以有多个 AuditRun；不能通过文件哈希跨案件共享敏感结果。

### AuditRun

约束：绑定不可变 InputSnapshot、FactSetSnapshot、AuditPlanSnapshot、知识与执行版本；状态变化使用乐观锁；完成前校验关键检查覆盖。

### RulePackage

约束：草稿与已发布版本分离；已发布版本不可原地修改；发布需要评测结果和批准记录。

### DecisionSnapshot

约束：绑定固定结果版本；记录决定人权限、理由、范围和时间；不覆盖原发现。

## 4. 核心不变量

1. 运行结果必须能定位到输入、计划、规则和模型版本；
2. 一个检查结果只能引用本运行获授权的事实和证据；
3. 未解决的关键事实冲突不能形成自动通过；
4. 所有关键槽位达到允许终态后检查才完成；
5. 执行完成不等于专业通过，专业通过不等于流程批准；
6. 新版本不修改旧快照和旧决定；
7. 模型、网络和人工等待不持有数据库事务。

## 5. 标识规范

业务对象使用不可推测的唯一 ID；外部 ID 单独保存。检查实例键至少包含：`tenant_id + run_id + domain + rule_package_version + rule_id + subject_ref`。

## 6. 待冻结问题

2026-09-17 旧 MVP 裁决如下，已被本轮目标修订：

- AuditCase 不绑定真实外部合同；ExternalBinding 仅用于 fixture 或 Mock Adapter；
- 预审结果不直接复用于正式流程，未来接入时创建新运行并重新校验版本；
- 一个 AuditRun 只包含一个主合同 DocumentVersion 和一个固定附件集合；
- 人工事实确认仅在案件/快照范围生效，不提升为租户级主数据；
- 首版不跨运行复制 CheckResult，只允许新运行引用旧结果用于差异展示。

本轮以[9 月 24 日方案](../../整体方案设计指导与实现层级架构.md)和[首期范围](../00-project/首期范围说明书.md)为准：待审对象仍是一份主合同及其附件，但可另行选择获授权的历史合同和同一我方法人项目客户合同，记录不同用途与固定版本；真实财务/合同只读接入在 MVP 后半段完成。AuditRun 绑定来源、关系、知识和权限视图的版本，不以 `case_id` 隐式获取其他合同。分类输出证据及不确定性后再编译固定计划；类别或材料更正创建新版本。

## 7. 聚合命令

| 聚合 | 命令 | 主要前置条件 | 产物 |
|---|---|---|---|
| AuditCase | create_case | 有 tenant、purpose、创建权限 | draft case |
| AuditCase | add_document_version | case 未取消、文件校验通过 | 不可变 DocumentVersion |
| AuditRun | start_run | case ready、输入固定、幂等键唯一 | queued run + plan snapshot |
| AuditRun | cancel_run | run 非终态、版本匹配 | cancelled run |
| FactSet | confirm_fact | 有字段权限、理由非空 | 新 FactSetSnapshot |
| HumanTask | decide_task | assignee/角色有效、task open | 决定记录 + 可能的新任务 |
| DecisionSnapshot | record_decision | run completed、结果当前、权限有效 | 不可变决定 |

### 工程实现注记（2026-09-29）

合同事实确认的首个开发切片由当前 reviewer 对运行结果中有来源引用的四类白名单候选逐项执行。服务端校验运行完成、候选值与该候选的全部证据 ID 完全匹配、引用属于当前仍授权的冻结文档；总价候选还要求冻结输入含金额权限。每次确认合并既有已核验值，生成新的 `FactSetSnapshot` 版本并保存操作者、时间、理由、候选值、确认值、原始证据和输入/运行身份。数据库运行角色仅有 SELECT/INSERT 权限，快照内容同时以 SHA-256 校验。重放同一幂等请求返回原快照。

运行启动时绑定同一 InputSnapshot 下最新的 FactSetSnapshot ID，任务载荷固定该绑定；Worker 校验快照内容哈希和输入身份后，才把其中 `verification_status=verified` 的值提供给 `RulePlan`。历史运行不回写。当前字段权限模型仍是案件 reviewer + 四个事实谓词白名单，其中合同总价额外依赖 `require_amount`；尚无更细的逐字段角色授权矩阵。该切片不代表本候选规则或映射词表获得法务/企业批准。

命令失败必须返回可区分的 `validation_error`、`forbidden`、`not_found`、`conflict` 或 `precondition_failed`，不得静默降级。
