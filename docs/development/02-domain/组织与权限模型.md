# 组织与权限模型

## 适用范围

系统按租户隔离用户、组织、角色、主体台账和业务数据。管理员在系统内维护组织架构和账号；每个账号隶属一个组织部门，并可被分配一个或多个角色。

组织部门用于管理人员归属，不会自动授予功能权限，也不会自动扩张案件数据范围。角色控制用户可使用的功能；案件成员关系继续控制用户可访问的案件，逐份材料授权继续控制合同内容的读取范围。

## 功能权限

| 权限 | 功能范围 |
|---|---|
| `cases.use` | 查看和处理自己有权访问的案件、材料和审核结果 |
| `tasks.use` | 查看和处理分配给自己的人工任务 |
| `entity_registry.use` | 搜索和选择已启用的法人主体 |
| `entity_registry.manage` | 新增、维护、启用和停用主体台账记录 |
| `entity_corrections.use` | 查看主体纠错队列并执行经授权的案件主体更正 |
| `admin.manage` | 管理组织、账号、角色和功能权限 |

系统内置角色：

| 角色 | 权限 |
|---|---|
| 系统管理员 | 全部功能权限及组织账号管理 |
| 合同审核员 | 合同审核、人工任务、主体查询 |
| 主体管理员 | 主体查询、主体管理、主体纠错 |

系统管理员可以建立自定义角色并勾选可用功能权限；一个账号可以分配多个角色。主体台账管理和案件主体纠错是不同的权限：维护组织级主体资料不自动开放案件纠错。

## 案件和材料数据范围

功能权限决定页面和 API 是否允许执行某类操作；`case_members` 决定用户能否读取具体案件；材料选择、用途授权和有效期决定系统能否读取被授权文件。拥有合同审核功能不会自动加入案件成员，也不会授予合同文本或金额读取权限。

案件主体确认后，主体 UUID 成为案件及其材料的范围边界。确认错误时，具备纠错权限的主体管理员可按纠错流程更正；系统保留审计记录，撤销旧材料选择和读取授权，并使既有审核运行失效。台账主体停用后不能再被新案件选择，但不会改写既有案件的历史主体绑定。

## 登录、账号与密码管理

- 登录页只提供账号和密码输入，不创建管理员、不创建组织，也不提供首次初始化入口。
- 新租户的首个系统管理员由部署人员在可信服务端终端运行 `uv run python -m contract_app.bootstrap_admin` 创建；该操作仅可成功一次。
- 首个管理员登录后，在“组织与权限”中创建部门、成员账号和角色，并分配账号所属部门与角色。
- 新建账号或管理员重置密码后，首次登录必须修改密码。停用账号或重置密码会撤销该账号的现有会话。
- 浏览器使用服务端会话 Cookie；密码仅保存为 scrypt 哈希，会话令牌仅保存 SHA-256 摘要。

## 实现边界

API 对每个功能端点执行角色权限校验；前端菜单和路由仅提供导航与提示，不作为授权来源。OIDC 可作为身份认证来源，但系统内的角色、案件成员关系和材料授权仍由本系统管理。
