# 销售审查证据与引用规范

## 1. 证据类型

| kind | 必要内容 | 用途 |
|---|---|---|
| `document_span` | 文档、版本、哈希、页码、条款路径、Unicode 偏移、短引文 | 证明固定版本合同文字 |
| `source_record` | 系统、记录 ID、JSON Pointer、快照/观察时间 | 证明产品、财务、交付或安全系统记录 |
| `calculation` | 输入引用、公式、币种/税/单位、舍入、执行器版本 | 证明价格、账期、上限或日期计算 |
| `normative_reference` | 规范 ID、版本、条款、效力、法域、时点和核验来源 | 支持法律或制度判断 |
| `human_confirmation` | 人员/角色、权限、确认、理由和时间 | 证明有权人员确认能力、事实或决定 |
| `absence_evidence` | 文件范围、解析覆盖、搜索方法、术语和未命中说明 | 支持在声明范围内未找到条款 |

模型推理、销售口头表态和“行业通常如此”不是独立证据。

## 2. 合同定位

`document_span` 至少包含：

```json
{
  "evidence_id": "ev-001",
  "kind": "document_span",
  "document_id": "doc-customer-msa",
  "document_version": "v4",
  "content_hash": "sha256:...",
  "page": 12,
  "clause_path": "第10条/10.3",
  "unicode_start": 18230,
  "unicode_end": 18402,
  "quote": "……",
  "support": "direct"
}
```

坐标必须来自解析器；缺失时设为 `null` 并记录限制。证据不能跨版本复用。表格补充表、行、列或单元格坐标。

## 3. 能力证据

合同要求与我方能力必须分开：

- SLA、恢复目标、数据位置、删除、加密、审计报告、认证、支持时间等必须关联产品/运维/安全记录或有权确认；
- 路线图、计划能力和历史个案只作背景，不能证明当前承诺可兑现；
- 能力证据与合同承诺冲突时保留双方证据，槽位置为 `conflicted` 或 `human_review`；
- 销售人员无权批准的承诺不得升级为企业事实。

## 4. 缺失性证据

使用 `not_found` 前必须确认：应检查的客户纸、附件、网页、采购政策、订单和安全/DPA 文件已获得；解析完整；标题、同义词、定义、正文和交叉引用均已检查。否则使用 `needs_material`、`data_unavailable` 或 `undetermined`。

## 5. 支持强度

- `direct`：直接支持值或判断；
- `corroborating`：需与其他证据共同支持；
- `context`：只提供背景；
- `contradicting`：与候选值冲突，必须保留并路由。

高风险结论至少需要直接合同证据；若涉及运营能力、企业政策或规范，还必须分别有相应证据。

## 6. 法律与制度引用

优先级：规则包绑定的已核验规范快照、批准知识库、用户提供且可核验材料、其他待核实来源。精准条款号、监管时限、数据出境门槛和案例结论具有时效性，未核验不得进入确定性结论。

每个引用记录名称、版本/公布号、效力、生效时点、法域、条款、核验来源和原文定位。不能核验时不猜条款号或法条原文，转 `human_review`。

## 7. 冲突与决定

- 保存合同版本、系统记录和人工确认的全部候选；
- 不自行选择“更符合业务常识”的值；
- 审批决定作为独立 `DecisionSnapshot`，不覆盖原发现；
- 旧交易、历史接受或客户声称不是本次已批准例外；
- 只有有权确认或确定性优先级规则解决后，槽位才可 `filled`。

## 8. 保密与共享

最小化引用敏感内容并对非必要个人信息脱敏。合同和审查结果不得上传未授权服务。面向客户的修订稿不得包含内部谈判底线、风险评估、审批意见或保密法律分析。
