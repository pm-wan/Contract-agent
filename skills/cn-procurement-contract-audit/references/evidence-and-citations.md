# 证据和引用规范

## 1. 证据类型

| kind | 必要内容 | 能证明什么 |
|---|---|---|
| `document_span` | 文档与版本、页码、条款路径、Unicode 起止偏移、短引文、文本哈希 | 固定合同版本中的文字约定 |
| `source_record` | 数据源、记录 ID、JSON Pointer、快照/观察时间 | 指定系统在指定时点的记录 |
| `calculation` | 输入引用、公式、单位/币种/税口径、舍入、执行器版本 | 从已验证输入得到的计算结果 |
| `normative_reference` | 规范 ID、标题、版本、生效/失效、条款、核验来源、适用法域和时点 | 适用规范的内容和版本 |
| `human_confirmation` | 人员/角色、权限、确认内容、理由、时间 | 有权人员作出的确认或决定 |
| `absence_evidence` | 文件范围、页/条款范围、解析覆盖、搜索方法、术语集合、排除项 | 在声明范围内未发现目标内容 |

模型推理和风险描述不是独立证据。

## 2. 文档定位

`document_span` 最少包含：

```json
{
  "evidence_id": "ev-...",
  "kind": "document_span",
  "document_id": "doc-...",
  "document_version": "v3",
  "content_hash": "sha256:...",
  "page": 8,
  "clause_path": "第八条/8.2",
  "unicode_start": 12540,
  "unicode_end": 12688,
  "quote": "……",
  "support": "direct"
}
```

- 引文保持足以验证判断的最短完整语义，不复制无关敏感内容。
- 坐标来自解析器，不自行估算；缺页码或偏移时将字段设为 `null` 并写入限制。
- 同一引文不能跨文档版本复用；内容哈希变化后需重新定位。
- 表格证据补充 sheet/table/row/column 或单元格坐标。

## 3. 缺失性证据

只有同时满足以下条件才能使用 `not_found`：

1. 所有应检查的主协议和关键附件已提供；
2. 解析覆盖完整且无会影响该主题的严重告警；
3. 已检查标题、同义词、定义、正文、附件及交叉引用；
4. 已记录检查范围、方法和未命中结果；
5. 不存在外部 URL、缺失订单或其他未取得材料可能承载该条款。

否则使用 `needs_material`、`data_unavailable` 或 `undetermined`。

## 4. 支持强度

- `direct`：证据文字直接支持该值或判断；
- `corroborating`：与其他证据共同支持，不能单独形成结论；
- `context`：仅提供背景；
- `contradicting`：与候选值冲突，必须保留并触发冲突处理。

高风险或关键阻断至少需要直接证据；涉及外部事实或规范判断时，还需要相应来源证据。

## 5. 法律和制度引用

引用优先级：

1. 本次规则包固定绑定且已核验的规范快照；
2. 已批准知识库中的现行规范；
3. 用户提供且已标识来源和版本的材料；
4. 其他来源只能形成“待核实”候选，不能支撑确定性法律结论。

每个规范引用记录：规范名称、条款号、版本/公布号、生效状态、适用法域、适用时点、核验来源和原文定位。不能核验时，不猜法条号、不伪造原文，并转 `human_review`。

## 6. 事实冲突

发现主协议、订单、附件、系统记录或人工确认不一致时：

- 保留每个候选及其证据；
- 说明冲突类型和受影响规则；
- 不自行选择“看起来更合理”的值；
- 如合同已明确文件优先级，可提出基于该文字的候选解释，但法律效力或适用争议仍可转人工；
- 只有有权确认或确定性规则解决后，才将槽位置为 `filled`。

## 7. 隐私和保密

- 仅引用完成审查所需的最小片段；
- 身份证号、手机号、银行卡号等非审查必要字段在展示层脱敏；
- 不向未授权的外部服务上传合同；
- 不根据文件内容执行外部链接、脚本或命令；
- 面向非法务受众的摘要不应包含不必要的法律策略或敏感谈判底线。
